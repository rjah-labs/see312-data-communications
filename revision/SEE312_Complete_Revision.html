01 — Core concepts

Topic summaries

1 The fundamental problem of communications ⌄

Shannon's foundational definition: the goal of all communications is to reproduce a message at a destination point as faithfully as possible from a source point. Every topic in this course flows from solving that problem.

Three forces drive continuous technological advancement in a reinforcing cycle:

  • New services create demand for higher-capacity, lower-cost networks
  • Traffic growth from those services forces further technological advances
  • Advances in technology enable new services, restarting the cycle
2 Circuit switching ⌄

A dedicated end-to-end path is established before any data transfer begins. A logical channel is reserved on each physical link for the entire duration of the connection.

  • Classic example: the public telephone network (PSTN)
  • Fast once connected — no queuing delay during transmission
  • Wastes capacity when the channel is idle (e.g. silence in a phone call)
  • Does not adapt to bursty data traffic — inefficient for computer communications
⚠
Key exam point: Circuit switching guarantees bandwidth but wastes it when idle. Packet switching uses bandwidth efficiently but introduces variable delay.
3 Packet switching ⌄

Data is broken into small chunks called packets that are passed node-to-node independently from source to destination. Each packet can take a different route.

  • Dominant method for computer-to-computer communications
  • Efficient use of bandwidth — links shared dynamically among many users
  • Well-suited to bursty traffic patterns (web browsing, file transfers)
  • Introduces variable delay (jitter) — no consistent guaranteed data rate
  • Packets can arrive out of order — upper layers must reassemble
4 Frame Relay and ATM ⌄

Frame Relay is a high-speed WAN technology achieving up to 2 Mbps. It strips out most error-control overhead, relying on the low error rates of modern digital links for its speed. It is a streamlined packet-switching variant.

ATM (Asynchronous Transfer Mode), also called cell relay, uses fixed-length packets called cells — unlike conventional packet switching which uses variable-length packets. Key characteristics:

  • Fixed cell size simplifies hardware switching, enabling very high speeds (tens of Mbps to Gbps)
  • Supports multiple channels with data rates dynamically assigned on demand
  • Blends features of both circuit switching (predictable channels) and packet switching (efficient bandwidth use)
  • Designed to carry voice, video, and data on the same network
5 What drove demand for higher-speed networks? ⌄

Three key changes created demand for far greater network capacity:

  • High-speed LANs — explosive growth in PC computing power established LANs as core computing platforms, creating needs like centralised server farms and power workgroups requiring high-bandwidth interconnection
  • Corporate WAN evolution — traffic patterns became unpredictable, telecommuting grew, intranet computing expanded, and more data moved off-premises to cloud services
  • Digital image and video traffic — the shift to digital electronics dramatically increased image and video traffic, requiring far greater network capacity than text-only communications
6 Network convergence and QoS ⌄

Network convergence means modern networks simultaneously carry voice, data, image, and video over integrated infrastructure — previously these required entirely separate networks.

QoS (Quality of Service) is the ability of a network to provide different levels of service to different traffic types. This becomes essential in a converged network because:

  • Voice and video are delay-sensitive — they require bounded latency and jitter
  • Bulk file transfers can tolerate delay but not data loss
  • Without QoS, all traffic competes equally — real-time traffic suffers during congestion

06 — Transmission efficiency

Multiplexing & compression

Two primary techniques for improving the efficiency of a transmission facility — doing more with the capacity you have.

Multiplexing
Allows multiple devices or data streams to share a single transmission facility simultaneously. Instead of each device needing its own dedicated link, many users share the same physical medium.

This spreads infrastructure cost across more users, making the network economically viable. Without multiplexing, every device would need its own link to every destination — impractical at any scale.
Compression
Reduces the volume of data before transmission so that a lower-capacity, cheaper link can carry the same information — reducing transmission costs.

Compression means you can use a narrower (and cheaper) pipe to carry the same content, or carry more content over the same pipe. Critical for video and image transmission where raw data volumes are enormous.

01 — Core concepts

Topic summaries

1 What is a protocol? ⌄

A protocol is a set of rules governing the exchange of data between communicating systems. Without a shared protocol, two physically connected devices cannot communicate — like two people speaking different languages.

Every protocol has three key elements:

  • Syntax — the format and structure of data; how bits and fields are arranged
  • Semantics — the meaning of each field; what action to take on a control message or error
  • Timing — speed matching between sender and receiver; correct sequencing of events
2 Why use a layered protocol architecture? ⌄

Real data communications involve many complex interdependent tasks. Breaking these into independent layers gives several advantages:

  • Each layer handles a distinct, well-defined function
  • Peer layers communicate via protocols; adjacent layers interact via service interfaces
  • Modularity — changes in one layer don't require changes in others (e.g. replacing Ethernet with Wi-Fi doesn't affect TCP)
  • Information hiding — upper layers don't need to know lower-layer implementation details
  • Standards can be developed independently per layer, promoting interoperability
3 TCP — Transmission Control Protocol ⌄

TCP is the primary transport-layer protocol. It provides:

  • Reliable, ordered, error-checked delivery (byte stream)
  • Connection-oriented — SYN/SYN-ACK/ACK handshake before data transfer
  • Flow control via window size field; congestion control
  • Segment tracking — sequence and acknowledgement numbers ensure all data arrives

TCP header is 20 bytes minimum (up to 60 bytes with options). Key flags: SYN (open connection), FIN (close), RST (abort), ACK (acknowledge), PSH (push to application), URG (urgent data).

4 UDP — User Datagram Protocol ⌄

UDP is the lightweight, connectionless alternative to TCP. It offers:

  • No guaranteed delivery, no ordering, no duplicate protection
  • Adds port addressing on top of IP — that's all it does
  • Optional checksum (mandatory in TCP)
  • Fixed 8-byte header: Source Port | Dest Port | Length | Checksum
  • Used by: DNS, SNMP, VoIP, live video streaming — where low latency beats reliability
5 IP — Internet Protocol & addressing ⌄

IP handles routing across multiple networks. It is connectionless and best-effort — no guaranteed delivery, no ordering (TCP handles that). Two levels of addressing are required:

  • IP address (32-bit IPv4 / 128-bit IPv6) — globally unique host identifier; routes the datagram to the correct machine
  • Port number (16-bit) — identifies the application process on the host; delivers data to the correct process (port 80 = HTTP, port 25 = SMTP, port 53 = DNS)

Together, IP address + port = socket, uniquely identifying a communication endpoint. Routers process only up to the IP layer — TCP is only implemented in end systems.

⚠
Exam note: IP does not check the payload for errors — only the header (header checksum field). Error checking of payload data is the responsibility of TCP. The header checksum must be recalculated at each router because the TTL field changes.
6 IPv4 vs IPv6 ⌄

The primary driver for IPv6 was address exhaustion. IPv4's 32-bit addresses provide only ~4.3 billion unique addresses — insufficient for the explosive growth of internet-connected devices.

  • IPv6 uses 128-bit addresses — astronomically larger space
  • Fixed 40-byte header (simpler, faster processing)
  • No header checksum (upper layers handle it)
  • No fragmentation in the base header (extension headers instead)
  • New fields: Flow Label (QoS support), Hop Limit (replaces TTL)

Splitting an IP datagram when it exceeds the MTU of a subnetwork. Reassembled at the destination only.

ISO's 7-layer reference architecture for protocol standardisation. A theoretical framework — TCP/IP is the deployed standard.

Application Q3. Trace encapsulation as a file is sent from Host A to Host B. Name the PDU at each layer. ⌄

  2. Transport (TCP) — adds TCP header → TCP segment
  3. Internet (IP) — adds IP header → IP datagram

At Host B, each layer strips its header and passes the remainder up until the original data reaches the correct application process.

Conceptual Q4. What is the purpose of the port number, and how does it differ from an IP address? ⌄

An IP address identifies a host on the internet — used by the IP layer to route the datagram to the correct machine.

A port number identifies a specific application/process on that host — used by TCP or UDP to deliver data to the correct process. Two levels are required because a host runs many applications simultaneously. Together they form a socket (e.g. 192.168.1.1:80 = HTTP server).

Conceptual Q6. What is the TTL field's purpose? What happens when it reaches zero? ⌄

TTL (Time to Live) prevents datagrams from circulating indefinitely due to routing loops. Each router decrements TTL by 1. When TTL reaches 0, the router discards the datagram and sends an ICMP "Time Exceeded" message back to the source. This bounds the lifetime of any datagram in the network.

Note: because TTL changes at every hop, the IP header checksum must be recalculated at every router.

Compare Q7. Why did TCP/IP dominate over OSI? ⌄
  • Timing — TCP/IP was mature and deployed when organisations needed interoperability; OSI protocols weren't finalised until TCP/IP was already the de facto standard
  • Simplicity — OSI's 7 layers are unnecessarily complex; session and presentation layers add overhead with limited practical benefit for most applications
  • Reality — OSI is a theoretical framework; TCP/IP is what actually runs the internet
Conceptual Q8. What drove IPv6 development, and what is the key technical difference from IPv4? ⌄

The primary driver was address exhaustion. IPv4's 32-bit addresses provide only ~4.3 billion addresses — insufficient for internet growth. IPv6 uses 128-bit addresses.

Additional technical changes: fixed 40-byte header, no header checksum, no base-header fragmentation, and a Flow Label field for QoS. The Hop Limit field replaces TTL.

Compare Q9. Distinguish elastic from inelastic traffic. Give one example of each and explain the design implication. ⌄

Elastic traffic (e.g. email): can tolerate variable delay and throughput. If the network is congested, the transfer takes longer but data still arrives correctly. Best-effort internet is sufficient.

Inelastic traffic (e.g. VoIP): has strict real-time requirements — minimum throughput, bounded delay, bounded jitter, acceptable packet loss. A delayed VoIP packet is worthless. This requires QoS mechanisms to reserve or prioritise network resources — best-effort delivery cannot guarantee these constraints.

Application Q10. A router receives a packet for Host B on a different subnetwork. Which TCP/IP layers does it process, and what does it do? ⌄

A router only processes up to the IP (Internet) layer. The steps:

  1. Strips the incoming frame header (network access layer)
  2. Reads the IP header — checks destination IP address
  3. Looks up the routing table to find the correct outgoing interface
  4. Decrements TTL; recalculates header checksum
  5. Wraps the IP datagram in a new frame header for the next subnetwork and forwards it

TCP is only implemented in end systems (hosts), not in routers. The router never reads inside the TCP segment or application payload.

01 — Core concepts

Topic summaries

1 Transmission media — guided and unguided ⌄

Data transmission requires a transmitter, a receiver, and a transmission medium. Media are classified into two broad types:

  • Guided (wired) — the signal is physically constrained to a cable: twisted-pair, coaxial cable, fibre-optic cable. Higher signal quality and security, but less flexibility.
  • Unguided (wireless) — electromagnetic waves propagate through free space (air, water, vacuum). More flexible but more susceptible to interference and eavesdropping.

Connections can also be characterised by topology: point-to-point (direct link between exactly two devices) or multi-point (more than two devices sharing the same medium).

2 Transmission direction — simplex, half-duplex, full-duplex ⌄
  • Simplex — one direction only. The sender can only send and the receiver can only receive. Example: broadcast television.
  • Half-duplex — both directions possible, but only one at a time. Example: walkie-talkie / police radio.
  • Full-duplex — both directions simultaneously. Example: telephone — you can talk and listen at the same time.
💡
Exam tip: A common mistake is confusing half-duplex with simplex. In simplex, one party can never transmit. In half-duplex, either party can transmit, but not at the same moment.
3 Time and frequency domain representations ⌄

Any signal can be described in two equivalent ways:

  • Time domain — amplitude as a function of time. What you'd see on an oscilloscope.
  • Frequency domain — amplitude (and phase) of each sinusoidal component as a function of frequency. What you'd see on a spectrum analyser.

By Fourier analysis, any signal — no matter how complex — can be decomposed into a sum of sinusoidal components. This is the theoretical basis for why bandwidth matters: a channel that can only pass a limited range of frequencies will distort any signal whose components extend beyond that range.

A complete sine wave in the time domain maps to a single spike (at its frequency) in the frequency domain.

4 Spectrum and bandwidth ⌄

The spectrum of a signal is the range of frequencies it contains. The bandwidth is the width of that range — the difference between the highest and lowest frequencies in the signal.

  • Absolute bandwidth — the full width of the spectrum, from lowest to highest component frequency.
  • Effective bandwidth — the narrower band containing most of the signal's energy. Also commonly called just "bandwidth".
  • DC component — a zero-frequency component. Present if the signal has a non-zero average value over time.

Any digital waveform (square wave) theoretically requires infinite bandwidth because its Fourier series contains infinitely many harmonic components. In practice, channels are bandwidth-limited, so the signal is approximated — this approximation introduces distortion. The less bandwidth available, the greater the distortion and the higher the error rate.

5 Analog vs digital signals — why digital dominates ⌄

Analog signals are continuously varying; they can take any value over a continuous range. Digital signals switch between a finite set of discrete voltage levels.

Digital signals are preferred in modern communications because:

  • Cheaper to implement with VLSI technology
  • Less susceptible to noise — a received pulse just needs to be classified as "high" or "low", not measured precisely
  • Repeaters can fully regenerate a digital signal, eliminating accumulated noise (amplifiers for analog signals amplify noise too)

The disadvantage is greater attenuation across a given cable run, and the fact that digital signals require more bandwidth than an equivalent analog signal carrying the same information.

05 — Transmission impairments

Attenuation, delay distortion & noise

Transmission media are not perfect. The signal at the receiving end differs from the signal that was sent. The three main impairments are:

Attenuation

Signal strength falls off with distance. For guided media this is generally exponential, expressed in dB/km.

  • Received signal must be strong enough to detect
  • Must be significantly above noise floor
  • Attenuation increases with frequency — higher frequencies attenuate faster
  • Remedies: amplifiers (analog) or repeaters (digital); equalisation to flatten the frequency response
Delay distortion

Propagation velocity through a guided medium varies with frequency. Near the centre frequency, velocity is highest and falls toward the band edges.

  • Different frequency components of a signal arrive at different times
  • Causes intersymbol interference (ISI) — energy from one bit period "leaks" into adjacent bit periods
  • Particularly critical for digital data at high bit rates
  • Remedy: equalisation (adaptive filters)
Noise

Unwanted signals inserted between transmitter and receiver. There are four main types (see below).

  • Determines the minimum acceptable signal strength (SNR)
  • For analog: degrades signal quality
  • For digital: causes bit errors
  • Impulse noise is the primary cause of bit errors in digital systems

Types of noise

Thermal noise
Due to thermal agitation of electrons in a conductor. Present in all electronic devices. Uniformly distributed across all frequencies — called white noise. Given by N = kTB where k = Boltzmann's constant, T = temperature (K), B = bandwidth (Hz). Cannot be eliminated — sets the absolute noise floor.
Intermodulation noise
Produced when signals at different frequencies share a non-linear transmission medium. Sum and difference frequencies (f₁ ± f₂, 2f₁ ± f₂, …) are generated and interfere with other signals. Can occur in amplifiers operating outside their linear range.
Crosstalk
Electromagnetic coupling between adjacent wire pairs or circuits. A signal on one line is picked up by a neighbouring line. Common in telephone cables and PCB traces. Reduced by shielding, twisting, and physical separation.
Impulse noise
Irregular high-amplitude spikes of short duration caused by external electromagnetic interference (lightning, switching transients, motors). A minor annoyance for voice (a brief click) but devastating for digital data — a single spike can corrupt many bits. The primary cause of bit errors in digital transmission.

06 — Capacity limits

Nyquist bandwidth & Shannon capacity

Two fundamental results bound the maximum data rate achievable over a channel. Nyquist deals with a noiseless channel; Shannon accounts for noise.

Nyquist formula — noiseless channel
C = 2B log₂ M
C = channel capacity (bps)  |  B = bandwidth (Hz)  |  M = number of discrete signal levels
For binary (M = 2): C = 2B  →  maximum signal rate is 2B symbols/s for a channel of bandwidth B Hz
Shannon capacity formula — noisy channel
C = B log₂(1 + SNR)
C = theoretical maximum capacity (bps)  |  B = bandwidth (Hz)  |  SNR = signal-to-noise ratio (linear, not dB)
SNRdB = 10 log₁₀(signal power / noise power)  →  SNRlinear = 10^(SNRdB/10)
⚠
Exam note: Shannon gives a theoretical upper bound — it cannot be achieved in practice. Shannon tells you the maximum possible rate; Nyquist tells you the rate achievable with a given number of signal levels. Use Nyquist to find the required signal levels, Shannon to check if the SNR allows that data rate at all.

Interpreting the results: More signal levels M means more bits per symbol, increasing data rate for the same bandwidth. But more levels means the receiver must distinguish them more precisely — noise and distortion make this harder. Shannon's formula quantifies exactly how much noise limits this ability. There is always a trade-off between bandwidth, signal levels, noise tolerance, and data rate.

Conceptual Q1. Distinguish between guided and unguided transmission media. Give one example of each and one advantage of each. ⌄

Guided media physically constrain the signal to a cable path — e.g. twisted-pair copper cable. Advantage: predictable signal path, less susceptible to external interference, generally higher signal quality.

Unguided media allow electromagnetic waves to propagate through free space without a conductor — e.g. radio waves through air (Wi-Fi). Advantage: no physical infrastructure required between communicating devices — enables mobility.

Conceptual Q2. What is the difference between simplex, half-duplex, and full-duplex transmission? Give a real-world example of each. ⌄
  • Simplex — one direction only; e.g. broadcast television. The transmitter can only send; the receiver can only receive. No reverse channel.
  • Half-duplex — both directions possible but not simultaneously; e.g. walkie-talkie/police radio. Users must take turns; one must release before the other can transmit.
  • Full-duplex — both directions at the same time; e.g. a telephone call. Both parties can speak and listen simultaneously on the same connection.
Conceptual Q3. What is a Fourier series, and why is it important to data communications? ⌄

Fourier analysis shows that any periodic signal — no matter how complex — can be represented as a sum of sinusoidal components at different frequencies, amplitudes, and phases.

This is critical to data communications because it reveals the bandwidth requirements of any signal. A digital square wave, for example, contains infinitely many frequency components (odd harmonics). Any real transmission channel passes only a limited range of frequencies, so components outside that range are filtered out — causing the received signal to be a distorted approximation. The more bandwidth the channel provides, the better the approximation and the lower the error rate.

Numerical Q4. A sine wave has a frequency of 500 Hz. What is its period? What is the period of a 2 GHz signal? ⌄

500 Hz signal: T = 1/f = 1/500 = 0.002 s = 2 ms

2 GHz signal: T = 1/(2×10⁹) = 0.5×10⁻⁹ s = 0.5 ns

Key relationship: f = 1/T and T = 1/f. Period and frequency are inverses of each other — one high, the other low.

Conceptual Q5. Explain the three transmission impairments and how each affects digital signals. ⌄
  • Attenuation — signal strength decreases with distance. If the signal falls below the receiver's detection threshold or below the noise floor, bit errors result. Remedied by repeaters.
  • Delay distortion — different frequency components travel at different speeds through the medium. Energy from one bit period leaks into adjacent periods (intersymbol interference / ISI), causing the receiver to misread bits. Remedied by adaptive equalisation.
  • Noise — unwanted energy added to the signal. Impulse noise is the primary source of bit errors: a short high-amplitude spike can corrupt multiple consecutive bits. Thermal noise sets the fundamental SNR floor.
Conceptual Q6. Why is impulse noise more damaging to digital data than to analog voice? ⌄

For analog voice, a brief impulse noise spike is heard as a short click or pop. The human auditory system is tolerant of such brief disturbances — the brain essentially fills in the gap, and intelligibility is maintained. The distortion is noticeable but usually acceptable.

For digital data, a single high-amplitude spike that exceeds the decision threshold will corrupt every bit whose voltage level it masks during the spike's duration. At high bit rates (e.g. 100 Mbps), even a 1 μs spike can corrupt 100 bits — potentially destroying an entire frame or packet. This leads to retransmission or data corruption. There is no "filling in the gap" for binary data.

Numerical Q7. Apply the Nyquist formula: what is the maximum data rate of a noiseless 4 kHz channel using 8 signal levels? ⌄

Using C = 2B log₂ M:

  • B = 4000 Hz
  • M = 8 signal levels
  • log₂ 8 = 3
  • C = 2 × 4000 × 3 = 24,000 bps = 24 kbps

Note this assumes a noiseless channel. In practice, noise will reduce the achievable rate below this Nyquist bound.

Numerical Q8. Apply the Shannon formula: a channel has a bandwidth of 3100 Hz and an SNR of 30 dB. What is the theoretical capacity? ⌄

Step 1 — convert SNR from dB to linear: SNRlinear = 10^(30/10) = 10³ = 1000

Step 2 — apply C = B log₂(1 + SNR):

  • C = 3100 × log₂(1 + 1000)
  • C = 3100 × log₂(1001)
  • log₂(1001) ≈ 9.97
  • C ≈ 3100 × 9.97 ≈ 30,900 bps ≈ 31 kbps

This is the absolute theoretical maximum — no coding scheme can exceed it. This is roughly the capacity of a standard telephone voice channel.

The three worked cases illustrate the key relationships:

  • Case I (B = 4 MHz, rate = 2 Mbps): baseline — using 3 harmonics (f, 3f, 5f) at f = 1 MHz. One bit every 0.5 μs.

01 — Core concepts

Topic summaries

1 What is a transmission medium? ⌄

A transmission medium is anything that can carry information from a source to a destination. Transmission media sit below the physical layer and are directly controlled by it.

Media are classified as either guided (wired — physical path constrains signal) or unguided (wireless — signal propagates freely through air, vacuum, or water via an antenna).

  • For guided media, the medium itself is the primary limit on transmission performance (attenuation, bandwidth)
  • For unguided media, the signal bandwidth produced by the transmitting antenna is the key determinant — including the property of directionality (omnidirectional at low frequencies, highly directional at higher frequencies)
2 Key design factors for transmission systems ⌄

The primary goals of any transmission system are maximising data rate and distance. Four main design factors constrain both:

  • Bandwidth — greater signal bandwidth enables higher data rate. All other factors constant, more bandwidth → more capacity
  • Transmission impairments — attenuation limits distance. Twisted pair suffers most; optical fibre suffers least
  • Interference — competing signals in overlapping frequency bands distort or destroy signals. Guided media use shielding; unguided media rely on frequency allocation and directionality
  • Number of receivers — each attachment on a shared guided link introduces attenuation and distortion, reducing maximum distance and/or data rate
3 Twisted pair — UTP and STP ⌄

Two insulated copper wires arranged in a regular spiral pattern. Twisting reduces crosstalk interference between adjacent pairs; neighbouring pairs use different twist lengths to further reduce crosstalk.

  • UTP (Unshielded) — cheapest, easiest to install, susceptible to external electromagnetic interference. Standard office telephone wiring
  • STP (Shielded) — metal foil or braided-mesh surrounding each pair. Reduces noise penetration but is bulkier and more expensive
  • Analog: amplifiers every 5–6 km. Digital: repeaters every 2–3 km
  • Bandwidth limit ~1 MHz; data rates up to 100 Mbps (Cat 5) or even 10 Gbps over very short distances
  • Categories: Cat 3 (16 MHz, voice-grade), Cat 5 (100 MHz, data-grade), Cat 6 (200 MHz), Cat 7 (600 MHz, SSTP)
⚠
Exam note: Attenuation in twisted pair is a very strong function of frequency — it rises sharply with frequency. This is a key weakness compared to coaxial cable and optical fibre.
4 Coaxial cable ⌄

Coaxial cable has a central conductor (solid or stranded copper) enclosed in insulating sheath, surrounded by an outer conductor (metal foil or braid), then an outer plastic cover. The outer conductor acts as both a shield and the return path for the circuit.

  • Superior frequency characteristics to twisted pair — usable up to ~500 MHz for analog signals
  • Much less susceptible to interference and crosstalk due to shielded, concentric construction
  • Principal impairments: attenuation, thermal noise, and intermodulation noise (when multiple FDM channels are active)
  • Analog: amplifiers every few km (closer at higher frequencies). Digital: repeaters every ~1 km
  • Categorised by RG rating: RG-59 (75 Ω, Cable TV), RG-58 (50 Ω, Thin Ethernet), RG-11 (50 Ω, Thick Ethernet)
  • BNC connectors: BNC connector (cable to device), BNC T-connector (Ethernet branching), BNC terminator (prevents signal reflection)
5 Optical fibre — principles and benefits ⌄

Optical fibre transmits a signal-encoded beam of light using total internal reflection. It acts as a waveguide for frequencies in the range 1014 to 1015 Hz (near-infrared and visible light). A fibre cable has three concentric sections:

  • Core — glass or plastic, diameter 8–50 µm, carries the light
  • Cladding — glass or plastic coating, 125 µm diameter, lower refractive index; acts as reflector to confine light in the core
  • Jacket — outer plastic layer; protects against moisture, abrasion, crushing

Key advantages over twisted pair and coaxial cable:

  • Greater capacity — data rates of hundreds of Gbps over tens of km have been demonstrated
  • Smaller size and lighter weight — significant advantage in cramped conduits
  • Lower attenuation — constant over a wide frequency range; repeater spacing in the tens of kilometres, with hundreds of km demonstrated
  • Electromagnetic isolation — immune to external EM interference, impulse noise, and crosstalk; also difficult to tap (high security)

Light sources: LED (cheaper, wider operating temperature range, longer life) or ILD/Injection Laser Diode (more efficient, higher data rate).

6 Wireless transmission and antenna gain ⌄

Unguided media use antennas to radiate electromagnetic energy. Three frequency ranges are used for communications:

  • 30 MHz – 1 GHz: Broadcast radio (FM radio, VHF/UHF TV) — omnidirectional
  • 1 – 40 GHz: Microwave (terrestrial and satellite) — highly directional; requires line-of-sight
  • 3×1011 – 2×1014 Hz: Infrared — local point-to-point; blocked by walls

Antenna gain measures directionality — power output in a particular direction compared to an isotropic (omnidirectional) antenna. Increased power in one direction comes at the expense of others. Antenna gain and effective area Ae are related by:

7 Terrestrial microwave and satellite ⌄

Terrestrial microwave uses parabolic dish antennas (~3 m diameter) to focus a narrow beam. Typical frequencies: 1–40 GHz (4–6 GHz and 11 GHz most common). Repeaters every 10–100 km (fewer than coaxial cable, but line-of-sight required). Main impairments: attenuation with distance², rainfall above 10 GHz, and interference.

  • 12/14-GHz band: uplink 14–14.5 GHz, downlink 11.7–12.2 GHz

04 — Optical fibre

Fibre transmission modes

Three propagation modes exist, determined by the core radius and the refractive index profile. Each involves a different trade-off between cost, distance, and signal quality.

Step-index Multimode

Light enters at shallow angles and reflects back and forth off the core-cladding boundary. Multiple paths (modes) exist — each with a different path length and travel time.

This causes modal dispersion: light pulses spread out in time, limiting the data rate. Best suited to very short distances only.

Graded-index Multimode

The refractive index of the core varies — higher at the centre, lower at the edges. Light near the periphery travels faster but over a longer curved path.

This equalises arrival times across modes, reducing dispersion compared to step-index. Commonly used in LANs.

Single Mode

Core radius is reduced to the order of one wavelength — only a single mode (the axial ray) can propagate. No modal dispersion occurs.

Superior performance — highest data rates over the longest distances. Used in long-haul telephone and cable TV trunk applications.

Free-space loss equations

Free-space loss quantifies signal dispersion with distance — even with no atmospheric effects, power spreads over an ever-larger sphere.

EQ 4.3 — Isotropic antenna (fixed wavelength)

Pt/Pr = (4πd/λ)² = (4πfd/c)²

LdB = 20log(f) + 20log(d) − 147.56 dB

Interpretation: loss increases with frequency. Higher f → worse loss (under isotropic assumption).

EQ 4.4 — Fixed antenna area (accounts for antenna gain)

Pt/Pr = (4π)²d² / (GrGtλ²) = (λd)² / (ArAt)

LdB = −20log(f) + 20log(d) − 10log(AtAr) + 169.54 dB

Interpretation: loss decreases with frequency when antenna area is fixed, because higher-frequency antennas have higher gain for the same physical size.

⚠
The key insight: The two equations are not contradictory. Eq. 4.3 holds wavelength (λ) constant. Eq. 4.4 holds physical antenna area (A) constant. For the same physical antenna, higher frequency → shorter λ → higher gain G = 4πA/λ². This gain more than compensates for the increased free-space loss — resulting in a net gain at higher frequencies.

06 — Propagation

Wireless propagation modes

Ground Wave (<2 MHz)

Follows the curvature of the Earth beyond the visual horizon. Signal induces currents in the Earth's surface, slowing the wavefront near the ground and bending it downward.

Electromagnetic waves in this band scatter in the atmosphere and do not penetrate into the upper atmosphere. Classic example: AM radio.

Sky Wave (2–30 MHz)

Signal reflects (actually refracts) off the ionised upper atmosphere (ionosphere) back to Earth. Can bounce multiple times between ionosphere and Earth's surface.

Allows signals to propagate thousands of kilometres from the transmitter. Used by: amateur radio, CB radio, international shortwave broadcasts (BBC, Voice of America).

Line of Sight (>30 MHz)

Above 30 MHz, neither ground wave nor sky wave operates — the ionosphere becomes transparent. Transmitter and receiver must be within effective line-of-sight.

Microwaves are slightly bent by the atmosphere (following Earth's curvature), so the radio horizon extends slightly beyond the optical horizon. Used by: microwave links, satellite, Wi-Fi, mobile telephony.

Refraction

Refraction occurs when an electromagnetic wave moves between media of different density — its speed changes, causing the direction to bend at the boundary. The refractive index = sin(angle of incidence) / sin(angle of refraction) = ratio of velocities in the two media.

In the atmosphere, refractive index normally decreases with altitude (denser air near the ground). This causes radio waves to travel slightly slower near the ground → wavefront tilts downward → signals follow a path that bends slightly toward the Earth, extending the effective range of LOS links beyond the geometric optical horizon.

07 — Glossary

Key terms

Guided media
Transmission media that provide a physical path constraining the signal — twisted pair, coaxial cable, optical fibre. Medium properties dominate performance.
Unguided media
Wireless media where signals propagate freely through air or vacuum via an antenna. Antenna characteristics and signal bandwidth dominate performance.
Attenuation
Loss of signal power with distance. Measured in dB/km. A fundamental limit on how far a signal can travel before a repeater or amplifier is required.
Crosstalk
Unwanted coupling of a signal from one conductor into an adjacent one. Twisting pairs and shielding both reduce crosstalk. Near-end crosstalk (NEXT) is the primary concern.
Total internal reflection
The mechanism by which light is confined to the core of an optical fibre. Occurs when light hits the core-cladding boundary at an angle less than the critical angle.
Modal dispersion
In multimode fibre, different light paths (modes) have different lengths, causing light pulses to spread out in time. Limits data rate. Eliminated in single-mode fibre.
Antenna gain
A measure of directionality — power output in a given direction relative to an isotropic antenna. Gain in one direction comes at the expense of other directions. G = 4πAe/λ².
Free-space loss
Signal power reduction due to spherical spreading with distance — even with no obstructions or absorption. Scales with d² and (for isotropic model) f².
Isotropic antenna
A theoretical point source that radiates equally in all directions with a perfectly spherical radiation pattern. Used as the reference for antenna gain measurements (dBi).
Multipath interference
Reflections from terrain, water, or buildings create multiple copies of the signal with different delays. The composite received signal may be reinforced or cancelled depending on phase relationships.
Transponder
A frequency band on a communication satellite. The satellite receives signals on an uplink frequency, amplifies them, and retransmits on a different downlink frequency.
WDM (Wavelength Division Multiplexing)
A technique used on optical fibre to transmit multiple signals simultaneously at different wavelengths (colours) of light, dramatically increasing total capacity.

Conceptual Q1. Distinguish between guided and unguided transmission media. What is the primary performance-determining factor for each? ⌄

Guided media (twisted pair, coaxial cable, optical fibre) provide a physical path that constrains and directs the signal. The medium itself is the primary determinant of performance — its bandwidth, attenuation per unit length, and susceptibility to interference define what is achievable.

Unguided media use antennas to radiate signals freely through air, vacuum, or water. The primary performance determinant is the bandwidth of the signal produced by the antenna, and the directionality of transmission. The medium (air) imposes relatively little constraint — antenna and signal design matter most.

Conceptual Q2. Why does twisting the wire pairs in UTP reduce interference? Why do adjacent pairs use different twist lengths? ⌄

Twisting causes any external interference to be picked up alternately by each wire in the pair. Because the two wires are used differentially (the signal is the difference between them), equal noise picked up by both cancels out at the receiver — a process called common-mode rejection. Low-frequency interference is particularly reduced by the twist.

Adjacent pairs in the same cable use somewhat different twist lengths so that the coupling pattern between any two pairs differs — making it less likely that their crosstalk contributions constructively add up. This further reduces inter-pair crosstalk.

Conceptual Q4. Describe the structure of a coaxial cable. Why is it significantly less susceptible to interference than twisted pair? ⌄

Coaxial cable has four concentric layers: a central solid or stranded copper inner conductor, surrounded by an insulating dielectric, then an outer conductor of metal foil or braided mesh, and finally a plastic outer sheath.

The outer conductor acts as a Faraday cage — it completely encloses the inner conductor and blocks external electromagnetic fields from reaching it. External interference induces currents only in the outer conductor, not the inner one that carries the signal. The concentric geometry means the return current flows uniformly around the signal conductor, producing no net external magnetic field and providing excellent shielding in both directions.

By contrast, a twisted pair has no enclosing shield — it relies only on the differential cancellation from twisting, which becomes less effective at higher frequencies.

Compare Q5. Compare the three optical fibre transmission modes. Which is used for long-haul telephony and why? ⌄
  • Step-index multimode — large core, light bounces at varying angles. Multiple modes arrive at different times (modal dispersion), limiting data rate and distance. Used only for very short links.
  • Graded-index multimode — refractive index varies across the core, equalising travel times and reducing dispersion. Better performance than step-index; used in LANs.
  • Single mode — core is reduced to ~1 wavelength; only one propagation path exists. No modal dispersion. Highest data rates over the greatest distances.

Single mode is used for long-haul telephony because eliminating modal dispersion allows very high data rates to be maintained over tens to hundreds of kilometres between repeaters — critical for intercity and submarine cables where the cost of repeaters is significant.

Conceptual Q6. List four key advantages of optical fibre over coaxial cable and twisted pair. ⌄
  • Greater capacity — potential data rates of hundreds of Gbps, vastly exceeding copper media (practical maximum ~hundreds of Mbps for coaxial, ~100 Mbps – 10 Gbps for twisted pair over short distances)
  • Lower attenuation — 0.2–0.5 dB/km and constant over a wide frequency range, versus sharply frequency-dependent attenuation in twisted pair. Repeater spacing of 40+ km vs 1–2 km for copper
  • Electromagnetic isolation — immune to external EM fields, impulse noise, and crosstalk. Also difficult to tap, providing inherent security
  • Smaller size and lighter weight — significant practical advantage in conduits and underground runs; reduces structural support requirements
Application Q7. A terrestrial microwave link operates at 11 GHz with repeater spacing of 50 km. Explain why rainfall is a concern at this frequency, and what propagation mode is used. ⌄

Propagation mode: Line-of-sight (LOS). Above 30 MHz, the ionosphere is transparent — ground wave and sky wave propagation do not operate. Terrestrial microwave requires direct LOS paths between dish antennas.

Rainfall concern: At frequencies above 10 GHz, the wavelength becomes comparable to the size of raindrops. Rain droplets scatter microwave signals, causing attenuation that can be significant enough to disrupt the link. The 11 GHz band is just above this threshold — heavy rainfall events will increase path loss beyond the link budget. This is the primary reason that very high frequency microwave links must have closer repeater spacing or additional power margins compared to lower-frequency links.

By comparison, attenuation from rainfall is much less significant at frequencies below 10 GHz (the 4/6 GHz satellite bands, for example).

Application Q8. Explain the three wireless propagation modes. At what frequency does each operate, and what is a real-world example of each? ⌄
  • Ground wave (below ~2 MHz): Signal follows the Earth's curvature. The wave induces surface currents that slow the wavefront near the ground, causing it to tilt downward and track the Earth. Example: AM broadcast radio. Can propagate well beyond the visual horizon.
  • Sky wave (2–30 MHz): Signal is refracted by the ionosphere back to Earth. Can bounce multiple times between the ionosphere and the surface, reaching thousands of kilometres. Example: international shortwave broadcasts (BBC World Service), amateur radio (HF bands).
  • Line-of-sight (above 30 MHz): The ionosphere becomes transparent — signals pass through rather than reflecting. Communication requires direct (or near-direct) LOS between antennas. Atmospheric refraction provides a slight extension of the radio horizon beyond the optical horizon. Examples: FM radio, mobile telephony (3G/4G/5G), Wi-Fi, microwave backbone links, satellite uplinks.
Application Q9. Using Equations 4.3 and 4.4, explain why increasing carrier frequency can either increase or decrease effective free-space loss, depending on the model. Reconcile the apparent contradiction. ⌄

Eq. 4.3 (isotropic antenna, fixed wavelength): LdB = 20log(f) + 20log(d) − 147.56 dB. Loss increases with frequency. At fixed distance, doubling frequency adds 6 dB of loss.

Eq. 4.4 (fixed antenna area At, Ar): LdB = −20log(f) + 20log(d) − 10log(AtAr) + 169.54 dB. Loss decreases with frequency.

Reconciliation: The difference lies in what is held constant. In Eq. 4.3, the antenna is isotropic — it has unit gain at all frequencies. In Eq. 4.4, the physical area of the antenna is fixed. As frequency increases (shorter wavelength), a fixed-area antenna captures more of the incident wavefront — its gain increases as G = 4πA/λ². This gain increase more than compensates for the increased free-space spreading loss. So for real antennas of fixed physical size, higher frequency is actually advantageous from a link budget perspective.

01 — Core concepts

Topic summaries

1 The four encoding combinations ⌄

Any combination of source data type (digital or analog) and carrier signal type (digital or analog) is possible and used in practice:

  • Digital data → Digital signal: simplest case; voltage pulses represent bits. Used in LANs. Equipment is less complex and cheaper than analog modulation.
  • Analog data → Digital signal: digitisation via PCM or delta modulation. Enables use of modern digital transmission and switching equipment.
  • Digital data → Analog signal: required when the medium only propagates analog signals (e.g. optical fibre, unguided media, public telephone network). Modem converts digital to analog.
  • Analog data → Analog signal: modulates a carrier to shift the signal to a different frequency band; enables frequency division multiplexing (FDM) over a shared medium.
2 Criteria for evaluating an encoding scheme ⌄

Five criteria determine the suitability of a digital signal encoding scheme for a given application:

  • Signal spectrum: absence of high-frequency components reduces required bandwidth. Absence of a DC component is desirable — it allows transformer coupling, which provides electrical isolation and reduces interference. Power should be concentrated in the middle of the transmission band.
  • Clocking: the receiver must determine the start and end of each bit. A self-clocking code embeds synchronisation in the signal itself (e.g. Manchester), removing the need for a separate clock line.
  • Error detection: some schemes build in a degree of error detection at the signal level (e.g. bipolar AMI's alternation property) allowing early detection.
  • Signal interference and noise immunity: some codes perform better in noisy environments. Performance is usually expressed as bit error rate (BER) vs signal-to-noise ratio.
  • Cost and complexity: higher signalling rate (baud) for the same data rate (bps) increases cost. Some codes require a higher baud rate than NRZ to achieve the same data rate.
3 NRZ codes (NRZ-L and NRZI) ⌄

NRZ-L (Nonreturn to Zero–Level): the most common and simplest scheme. Voltage is constant during a bit interval (no return to zero). Typically, a negative voltage represents one binary value and a positive voltage represents the other.

NRZI (NRZ Inverted): a form of differential encoding. The signal is changed (transition) at the start of a bit interval to encode a 1; no transition encodes a 0. Differential encoding is more reliable because detecting a transition is easier than comparing voltage levels, and the scheme is immune to polarity inversion on the line.

Problems with NRZ:

  • DC component — requires direct physical attachment (no transformer coupling)
  • Loss of synchronisation during long strings of 0s (NRZ-L) or 0s (NRZI) — clocks can drift
4 Bipolar schemes (AMI and Pseudoternary) ⌄

Bipolar schemes use three voltage levels: positive, zero, and negative.

Bipolar-AMI (Alternate Mark Inversion): a 0 is represented by no line signal (zero voltage). A 1 is represented by alternating positive and negative pulses. Advantages:

  • No DC component — transformer coupling is possible
  • Lower bandwidth than NRZ
  • Built-in error detection — any single bit error destroys the alternation property
  • Synchronisation maintained through runs of 1s (each 1 forces a transition)
  • Long runs of 0s remain a problem — no transitions for the receiver to lock on to

Pseudoternary: the inverse — a 1 is represented by no line signal, and a 0 by alternating positive and negative pulses. Neither scheme has a clear advantage; each is used in specific applications.

5 Biphase codes (Manchester and Differential Manchester) ⌄

Biphase codes guarantee at least one transition per bit period, making them self-clocking. There is always a transition in the middle of every bit interval.

Manchester: the mid-bit transition carries the data. A low-to-high transition = 1; high-to-low = 0. The IEEE 802.3 (Ethernet) standard specifies Manchester encoding for coaxial cable LANs.

Differential Manchester: the mid-bit transition is clocking only. Data is encoded at the start of the bit interval: a transition at the start = 0; no transition at the start = 1. Used by IEEE 802.5 (Token Ring).

Advantages over NRZ: self-clocking, no DC component, built-in error detection.

Disadvantage: maximum modulation rate is twice that of NRZ — requires correspondingly more bandwidth. Not used widely for long-distance links where this overhead is costly.

6 Scrambling — B8ZS and HDB3 ⌄

Scrambling solves the long-zero-run problem in bipolar AMI without increasing the signalling rate (unlike biphase codes). The idea: replace sequences of zeros that would cause a constant voltage line with a recognisable substitution pattern that introduces deliberate bipolar violations. The receiver detects the pattern and replaces it back with zeros.

B8ZS (Bipolar with 8-Zeros Substitution): used in North America. Any run of eight consecutive zeros is replaced with the pattern 000VB0VB, where V = bipolar violation (same polarity as the preceding pulse) and B = valid bipolar pulse (correct alternating polarity). Two deliberate violations allow the receiver to identify the substitution.

HDB3 (High-Density Bipolar 3): used in Europe and worldwide ITU-T systems. Any run of four zeros is replaced with one of two four-symbol patterns depending on whether the number of nonzero pulses since the last substitution is odd or even — this keeps the number of violations always even, preventing any net DC component:

  • Odd number of nonzero pulses since last substitution → substitute 000V
  • Even number of nonzero pulses since last substitution → substitute B00V
⚠
Exam note: In B8ZS, the polarity of V depends on the polarity of the last legitimate 1-pulse. If the last 1 was positive, the pattern is 000+−0−+. If negative, it is 000−+0+−. The key point: two code violations are deliberately introduced, which an AMI violation due to noise almost never produces in pairs.
7 Modulation rate vs data rate ⌄

These two quantities are often confused but are distinct:

  • Data rate (R) — bits per second (bps). The rate at which binary digits are transmitted.
  • Modulation rate (D) — baud (signal elements per second). The rate at which the signal level changes.

The relationship is: D = R / log₂M, where M is the number of distinct signal elements and L = log₂M is the number of bits per signal element.

  • NRZ-L: 1 bit per signal element → D = R (modulation rate equals data rate)
  • Manchester: 2 signal elements per bit → D = 2R (modulation rate is twice the data rate)
  • QPSK: 2 bits per signal element → D = R/2 (half the modulation rate of NRZ for the same data rate)

A higher modulation rate demands more bandwidth, which is why biphase codes are expensive for long-distance transmission.

04 — Digital to analog modulation

ASK, FSK, PSK & QAM

When a transmission medium only propagates analog signals (e.g. public switched telephone network, optical fibre, unguided media), digital data must be converted to an analog signal. A modem (modulator–demodulator) performs this. Three fundamental carrier parameters can be modulated:

ASK — Amplitude Shift Keying

Binary values encoded by different carrier amplitudes. Usually one amplitude is zero (carrier off = 0, carrier on = 1).

Pros: simple

Cons: susceptible to sudden gain changes; inefficient

Used for: up to 1200 bps on voice-grade lines; very high-speed optical fibre (on/off keying)

FSK — Frequency Shift Keying

Binary values encoded by two different frequencies near the carrier (BFSK). Less susceptible to error than ASK.

MFSK: more than two frequencies → each signal element encodes L = log₂M bits. More bandwidth-efficient but more error-prone.

Used for: up to 1200 bps on voice-grade lines; high-frequency radio; coaxial cable LANs

PSK — Phase Shift Keying

Binary values encoded by shifting the carrier phase. BPSK uses two phases (0° and 180°).

QPSK: four phases (0°, 90°, 180°, 270°) — each symbol encodes 2 bits. Symbol rate is half the bit rate → more bandwidth-efficient.

Differential PSK (DPSK): phase encoded relative to previous signal, not an absolute reference — easier to implement.

Quadrature Amplitude Modulation (QAM)

★ QAM — combination of ASK and PSK ⌄

QAM is a logical extension of QPSK. It sends two independent signals simultaneously on the same carrier frequency by using two copies of the carrier shifted 90° apart. Each copy is independently ASK modulated, then the two are summed and transmitted.

  • 4-QAM / QPSK: 2-level ASK on each quadrature channel → 4 possible states → 2 bits/symbol
  • 16-QAM: 4-level ASK on each channel → 16 states → 4 bits/symbol
  • 64-QAM: 64 states → 6 bits/symbol
  • 256-QAM: 256 states → 8 bits/symbol

Higher-order QAM achieves much higher data rates for a given bandwidth, but requires a higher SNR to maintain acceptable error rates — the constellation points are closer together and thus more susceptible to noise.

QAM is used in ADSL, cable modems, and wireless standards (Wi-Fi, LTE).

⚠
Exam note: In QPSK/QAM, the bit stream is split into two parallel streams (I and Q channels) each at R/2 bps. These are multiplied by cos(2πfct) and sin(2πfct) respectively, then added. The receiver demodulates each channel independently. This is why the symbol rate is half the bit rate for QPSK.

05 — Analog to digital conversion

PCM & Delta Modulation

Analog data must be converted to digital form to use modern digital transmission and switching equipment. Two main techniques: Pulse Code Modulation (PCM) and Delta Modulation.

A PCM — key details ⌄

Sampling theorem (Nyquist): if a signal is sampled at regular intervals at a rate at least twice the highest signal frequency, the samples contain all information in the original signal. For voice limited to 4000 Hz, 8000 samples/second suffices.

Quantising noise: because PAM samples are rounded to discrete levels, the original signal can only be approximated — it cannot be exactly recovered. This approximation error is called quantising noise. Each additional bit used for quantising increases the SNR by approximately 6 dB (a factor of 4 in power).

Nonlinear encoding (companding): PCM is refined by using unequally spaced quantisation levels — more levels for small amplitudes, fewer for large. This reduces overall distortion because quiet sounds (which dominate voice) are more finely resolved. Companding (compress + expand) achieves this in practice: the signal is compressed before quantising and expanded on receipt. Improvements of 24–30 dB in SNR have been achieved for voice signals.

Standard voice PCM: 8-bit samples at 8000 samples/second = 64 kbps per channel.

B Delta Modulation — key details ⌄

Delta modulation approximates the analog input with a staircase function that moves up or down by one step (δ) at each sampling interval. The output is a single bit per sample: 1 if the staircase moved up, 0 if it moved down.

Two noise types:

  • Quantising noise: when the signal changes slowly, the staircase oscillates around the true value. Increases as δ increases.
  • Slope overload noise: when the signal changes rapidly, the staircase cannot keep up. Increases as δ decreases.

The step size δ must be chosen to balance these two noise sources. Alternatively, the sampling rate can be increased — but this increases the output bit rate.

PCM vs Delta Modulation:

  • Delta modulation is simpler (only 1 bit per sample)
  • PCM achieves better SNR for the same bit rate
  • PCM is preferred for analog signal digitisation in practice
  • For good-quality voice: PCM typically uses 7 or 8 bits per sample at 8000 samples/s = 56–64 kbps

Conceptual Q1. What are the three elements of any protocol, and how do they apply to signal encoding? ⌄
  • Syntax — the structure of the signal: how voltage levels or frequencies are mapped to bits, the duration of each signal element, and the bit ordering
  • Semantics — what each signal state means: which voltage level represents a 1 vs a 0, how a bipolar violation is interpreted (deliberate substitution vs error)
  • Timing — when to sample the signal: both transmitter and receiver must share a clock (or use a self-clocking code) so that bit boundaries are correctly identified
Conceptual Q2. Why is a DC component in a digital signal problematic, and which encoding schemes avoid it? ⌄

A DC component (non-zero average voltage) causes problems because:

  • It prevents the use of transformer coupling between equipment — transformers only pass AC. Without transformers, direct physical attachment is needed, which is expensive and limits electrical isolation.
  • It can cause charge build-up on cable capacitance, degrading signal integrity over distance.

Schemes that eliminate DC component: Bipolar-AMI, Pseudoternary, Manchester, Differential Manchester, B8ZS, HDB3. NRZ-L and NRZI both have a DC component when data is not balanced between 0s and 1s.

Conceptual Q4. Explain why Bipolar-AMI provides built-in error detection that NRZ-L does not. ⌄

In Bipolar-AMI, successive 1-bits must alternate in polarity (positive then negative then positive, etc.). This is the alternation property. If any single bit error occurs — either deleting a pulse or creating a spurious one — the alternation property is violated. The receiver detects two consecutive same-polarity pulses and knows an error has occurred.

In NRZ-L, each bit is encoded solely by its voltage level. A bit error simply changes one level, but there is no structural rule that the receiver can check — no record of what the previous bit was. Therefore NRZ-L has no inherent error-detection capability at the signal level.

The tradeoff: AMI requires three voltage levels, meaning the receiver must distinguish between +A, 0, and −A rather than just two levels, which requires approximately 3 dB more signal power for the same error probability.

Application Q5. A data rate of 1 Mbps is to be transmitted using Manchester encoding. What is the minimum required bandwidth, and how does this compare to NRZ-L? ⌄

For Manchester encoding, each bit requires two signal elements (the bit interval is halved). Therefore the modulation rate is:

D = 2 × R = 2 × 1 Mbps = 2 Mbaud

The minimum bandwidth required is approximately equal to the modulation rate: 2 MHz (for Manchester at 1 Mbps).

For NRZ-L at the same data rate: D = R = 1 Mbaud, requiring approximately 1 MHz of bandwidth.

Manchester therefore requires twice the bandwidth of NRZ-L for the same data rate. This is why biphase codes are not used for long-distance links — the bandwidth cost is significant. However, Manchester gains self-clocking and no DC component in return.

Conceptual Q7. Explain the difference between ASK, FSK, and PSK. Which is most noise-immune and why? ⌄
  • ASK: encodes data by varying the carrier amplitude. Noise directly adds to amplitude, making ASK the most susceptible to noise and amplitude disturbances (e.g. sudden gain changes in the channel).

  • PSK: encodes data by shifting the carrier phase. The amplitude remains constant. Application Q8. A modem uses 8 phase angles and 2 amplitude levels (16 distinct signal combinations). What is the data rate if the modulation rate is 2400 baud? ⌄

Number of distinct signal elements: M = 8 phases × 2 amplitudes = 16

Bits per signal element: L = log₂M = log₂16 = 4 bits/symbol

Data rate: R = D × L = 2400 baud × 4 bits/symbol = 9600 bps

This is the scheme used in standard 9600 bps voice-grade modems (12 phase angles and four of them having two amplitudes, giving the same 16 combinations). The key insight: by encoding multiple bits per symbol (multilevel signalling), high data rates can be achieved within the limited 3.1 kHz voice telephone bandwidth.

Conceptual Q9. Describe the PCM process and explain what quantising noise is. How can it be reduced? ⌄

PCM process:

  1. Sampling: the analog signal is sampled at ≥ 2B samples/second (Nyquist rate) to capture all information. For voice (bandwidth ≤ 4000 Hz), this is 8000 samples/second.
  2. Quantising: each sample amplitude is rounded to the nearest of 2ⁿ discrete levels, where n is the number of bits per sample. This introduces an approximation error.
  3. Encoding: the quantised level is encoded as an n-bit binary number. The result is a serial bit stream.

Quantising noise is the error between the true sample amplitude and the nearest quantisation level. It is inevitable whenever a continuous amplitude is mapped to a discrete set of levels. The signal cannot be exactly reconstructed at the receiver.

Reducing quantising noise:

  • Increase the number of quantisation bits (n). Each additional bit adds approximately 6 dB of SNR improvement.
  • Use nonlinear (companded) quantisation — more levels for small amplitudes, fewer for large — to improve SNR for the amplitude range that occurs most often in practice.

01 — Core concepts

Topic summaries

1 The synchronisation problem ⌄

Transmitting a stream of bits from one device to another requires cooperation. One of the most fundamental requirements is synchronisation — the receiver must know the rate at which bits are arriving so it can sample the line at appropriate intervals to determine each bit's value.

If the receiver uses its own internal clock independently, a timing mismatch will eventually cause it to sample in the wrong bit period. Even a small clock drift accumulates over a long enough bit stream. Two strategies address this:

  • Asynchronous transmission — avoid long uninterrupted streams; re-synchronise on each character using start/stop bits
  • Synchronous transmission — embed clocking information in the data signal itself, or use a separate clock line; transmit large blocks without per-character overhead
2 Asynchronous transmission ⌄

In asynchronous transmission, data is sent one character at a time. The strategy avoids long uninterrupted bit streams, preventing clock drift from accumulating to a critical level.

  • The line idles at binary 1 between characters
  • Each character begins with a start bit (binary 0) that alerts the receiver
  • This is followed by 5–8 data bits, transmitted least-significant bit first
  • An optional parity bit follows for basic error detection
  • One or more stop bits (binary 1, matching idle) end the character; minimum length is 1, 1.5, or 2 bit times

The receiver re-synchronises at the start of each character and then simply samples at regular intervals. Because the re-sync happens so frequently, a modest clock drift between transmitter and receiver never accumulates enough to cause a sampling error within a single short character.

Overhead: For an 8-bit character with no parity and a 1-bit stop element, 2 of every 10 bits are framing overhead — a 20% overhead rate. Simple and cheap, but not efficient for large data blocks.

3 Synchronous transmission ⌄

For large blocks, synchronous transmission is more efficient. An entire block of data is formatted as a frame and transmitted continuously without per-character start/stop bits.

Because the block may be many bits long, the transmitter and receiver clocks must be tightly synchronised throughout. Two mechanisms:

  • Separate clock line — a dedicated wire carries the clock signal alongside the data
  • Embedded clock — the clocking information is encoded into the data signal itself (e.g. Manchester encoding, where every bit contains a transition), so no separate wire is needed

The frame also needs delimiters so the receiver can locate the start and end of a data block. A preamble (flag) marks the beginning and a postamble (flag) marks the end. The exact format depends on the data link protocol in use.

Synchronous transmission is much more efficient than asynchronous for large blocks — preamble, postamble, and control information typically total fewer than 100 bits, regardless of the size of the data payload.

4 Error detection — parity and CRC ⌄

Regardless of the transmission system's design, errors will occur. Error detection works by appending redundant bits (an error-detecting code) to the transmitted data. The receiver recalculates the code from the received bits and compares; a mismatch signals an error.

  • Parity bit — the simplest scheme. A single bit appended so the total number of 1s in the block is even (even parity) or odd (odd parity). Fails silently on an even number of errors. Even parity is typical for synchronous, odd for asynchronous. Not robust against burst errors.
  • CRC (Cyclic Redundancy Check) — far more powerful. A k-bit message is used to generate an (n−k)-bit Frame Check Sequence (FCS) by dividing the message by a predetermined generator polynomial P using modulo-2 arithmetic. The FCS is appended to form an n-bit frame T, which is exactly divisible by P. The receiver divides T by P — a non-zero remainder indicates an error.
💡
Modulo-2 arithmetic is binary addition with no carries — equivalent to the exclusive-OR (XOR) operation. Both addition and subtraction in mod-2 are identical to XOR. This is what makes CRC hardware implementation so efficient.
5 Checksum ⌄

The checksum is an error-detecting technique applicable to messages of any length. It is most common at the network and transport layers of the Internet (IP, TCP, UDP headers) rather than at the data-link layer.

  • The message is divided into equal m-bit segments (typically 16 bits in the Internet)
  • All segments are added using one's complement arithmetic
  • If the result overflows m bits, the overflow (carry) bits are wrapped around and added back
  • The sum is complemented (all 1s flipped to 0s and vice versa) to produce the checksum
  • The checksum is sent with the data

At the receiver, all received segments (including the checksum) are added in one's complement. If the result is all 1s (negative zero in one's complement), the data is accepted; otherwise it is discarded.

One's complement allows two representations of zero — positive zero (all 0s) and negative zero (all 1s). Adding a number and its complement yields negative zero (all 1s), which the receiver can check for directly.

6 Error correction (FEC) ⌄

Error detection requires retransmission when an error is found. For some applications this is impractical:

  • Wireless links can have high bit error rates, leading to excessive retransmissions
  • Satellite links have very long propagation delays — by the time an error is detected and retransmission requested, many more frames have already been sent

Forward Error Correction (FEC) adds enough redundancy to allow the receiver to correct errors without retransmission. A k-bit data block is mapped by an FEC encoder into an n-bit codeword (n > k) before transmission.

At the receiver, the FEC decoder has four possible outcomes:

  • No errors — the original codeword is recovered and data extracted
  • Correctable error pattern — the decoder identifies and corrects the errors, recovering the original data
  • Detectable but uncorrectable pattern — decoder reports an error but cannot fix it
  • Undetected error — rare; the error pattern happens to look like a valid codeword

The code rate is k/n (fraction of the codeword that is actual data). The redundancy is (n−k)/k. More redundancy provides greater error-correction power but reduces effective throughput.

7 Line configuration — topology and duplex ⌄

Topology describes the physical arrangement of stations on a transmission medium:

  • Point-to-point — exactly two stations (e.g. two routers connected directly)
  • Multipoint — more than two stations share the medium (e.g. a LAN). Traditionally used for mainframe-to-terminal links; now dominates in LANs.

Duplex describes the direction of data exchange:

  • Half-duplex (two-way alternate) — only one station transmits at a time. Requires only one data path. Suitable for terminal-to-computer interaction.
  • Full-duplex (two-way simultaneous) — both stations can transmit and receive simultaneously. Requires two data paths (or echo cancellation for a single path). More efficient for computer-to-computer data exchange.

CRC is the most powerful and most commonly used error-detecting code. It uses modulo-2 (XOR) division to generate a Frame Check Sequence that is appended to the data. The receiver redivides and checks for a zero remainder.

Definitions

n−k+1 bits
The predetermined pattern both sender and receiver agree on. Also called the generator polynomial.

n−k bits

n bits

Transmitter procedure

1
Append zeros: Multiply D by 2n−k, i.e. append (n−k) zero bits to the right of the message. This creates a (k + n−k) = n-bit number 2^(n-k) · D.
2

3

Transmit T.

1

2

06 — Forward Error Correction

Error correction & Hamming distance

Error correction embeds enough redundancy in the codeword that the receiver can identify and fix errors without retransmission. The key concept underpinning block codes is Hamming distance.

A Hamming distance ⌄

The Hamming distance d(v₁, v₂) between two equal-length bit sequences v₁ and v₂ is the number of bit positions at which they differ.

Example: v₁ = 011011, v₂ = 110001 → d(v₁, v₂) = 3 (positions 1, 2, and 5 differ).

For an error-correcting code:

  • To detect up to t errors: the minimum Hamming distance between any two valid codewords must be at least t + 1
  • To correct up to t errors: the minimum distance must be at least 2t + 1 — this ensures the received (corrupted) codeword is closer to the correct codeword than to any other valid codeword
B Block code intuition — worked example ⌄

Consider the mapping below. Only four of the 32 possible 5-bit patterns are valid codewords:

Data blockCodeword (5 bits)
0000000
0100111
1011001
1111110

If the received codeword is 00100, it does not match any valid codeword. The decoder assumes the closest valid codeword was sent. Comparing Hamming distances to each valid codeword, the closest match is 00111 (distance 2) — so the decoder outputs data block 01.

This is the fundamental principle: a received word is mapped to the nearest valid codeword in Hamming space.

C Code rate and redundancy ⌄

For a block code that maps k data bits to an n-bit codeword:

  • Code rate = k/n — the fraction of the codeword carrying actual data. A rate of 1/2 means half the transmitted bits are redundancy.
  • Redundancy = (n−k)/k — the overhead per data bit
  • Higher redundancy → more error-correction power → lower effective data throughput

Design choice: use FEC (lower throughput, no retransmission) or ARQ — Automatic Repeat reQuest (higher throughput when the channel is good, but breaks down on high-error wireless or long-delay satellite links).

Conceptual Q1. Why is synchronisation necessary in digital transmission, and what happens when clocks drift? ⌄

The receiver must sample the incoming signal once per bit time to determine each bit's value. It does this based on its own internal clock. If the receiver's clock is not precisely aligned with the transmitter's clock, the sampling point drifts relative to the actual bit boundaries.

With a small drift, the receiver samples correctly for many bits but eventually samples in the wrong bit period — reading a 0 when a 1 was sent (or vice versa). The longer the continuous bit stream, the greater the accumulated error. This is why synchronisation is fundamental: without it, no amount of error detection can compensate for systematic mis-sampling.

Conceptual Q2. Describe the structure of an asynchronous character frame. What is the purpose of each component? ⌄
  • Idle (binary 1) — the line rests at 1 between characters; same level as stop bits, so the transmitter can stay idle indefinitely
  • Start bit (binary 0) — signals the arrival of a new character; the transition from 1 to 0 triggers the receiver to begin sampling at one-bit-time intervals
  • Data bits (5–8) — the actual character data, transmitted least-significant bit first
  • Parity bit (optional) — for basic error detection; set so the total number of 1s is even (even parity) or odd (odd parity)
  • Stop element (1 or more binary 1s) — returns the line to idle; the minimum duration is 1, 1.5, or 2 bit times; no maximum. Ensures the line is at 1 before the next start bit can occur.

Conceptual Q7. Why is CRC superior to a parity bit for detecting burst errors? ⌄

A parity bit counts only whether the total number of 1s is even or odd. It fails silently whenever an even number of bits are flipped — and burst errors almost always flip 2 or more bits, so parity routinely misses them.

CRC, by contrast, uses polynomial division to create a highly non-linear relationship between the data bits and the FCS. A CRC-16 generator is guaranteed to detect:

  • All single-bit and double-bit errors
  • All burst errors of length ≤ 16 bits
  • All burst errors of length = 17 bits with probability 99.998%
  • All burst errors of length ≥ 18 bits with probability 99.997%

The residual (undetected) error rate with CRC is negligible for practical purposes.

Conceptual Q8. Explain the Internet checksum procedure at the sender and receiver. ⌄

Sender:

  1. Divide the message into 16-bit words
  2. Set the checksum field to zero
  3. Add all 16-bit words using one's complement addition (if the sum overflows 16 bits, the excess bits wrap around and are added back)
  4. Complement the result (flip all bits) — this is the checksum
  5. Send the message with the checksum appended

Receiver:

  1. Divide message + checksum into 16-bit words
  2. Add all words using one's complement addition (with wrap-around)
  3. Complement the result. If all 0s → message accepted. Otherwise → error, discard.

This works because adding a number and its one's complement always yields all 1s (negative zero). One more complement gives all 0s.

Compare Q9. Why is FEC preferred over ARQ for wireless and satellite links? ⌄

ARQ (Automatic Repeat reQuest) — the receiver detects errors and requests retransmission. This works well on reliable wired links but fails for two scenarios:

  • High-BER wireless links: a high bit error rate means many frames contain errors. Each retransmission also risks errors, causing a cascade of retransmissions that can saturate the link.
  • Satellite links: the propagation delay can be 250–500 ms each way. By the time the receiver detects an error and sends a retransmission request, the sender has already transmitted many more frames — all of which must be paused or discarded, wasting enormous bandwidth.

FEC adds redundancy so the receiver corrects errors locally, with no round-trip delay. The cost is reduced throughput (code rate < 1), but this is preferable to the link collapse that ARQ causes under adverse conditions.

Application Q10. A data link uses half-duplex over a point-to-point topology. Describe the topology and duplex, and give a practical example where this configuration is appropriate. ⌄

Topology: Point-to-point — exactly two stations connected by a single transmission medium. No other stations share the link, so there is no access-control problem.

Duplex: Half-duplex (two-way alternate) — only one station may transmit at a time. Both stations can transmit and receive, but not simultaneously. Only one physical data path is required.

Practical example: A walkie-talkie (push-to-talk radio) link between two people. One presses their button and speaks (transmits); the other listens (receives). They cannot talk simultaneously on the same frequency — one must finish and say "over" before the other begins. The same model historically applied to terminal-to-mainframe interaction over a serial line.

Full-duplex would require either two separate frequencies (or two wires) and is used when continuous bidirectional traffic is needed — e.g. a telephone call or a TCP connection between two computers.

01 — Core concepts

Topic summaries

1 Why multiplexing? The efficiency argument ⌄

Multiplexing allows several transmission sources to share a single high-capacity link. The motivation is economic: cost per kbps decreases as the data rate of a transmission facility increases. Most individual devices only need a modest share of a high-speed link's capacity — it makes little sense to dedicate an entire expensive trunk line to a single low-rate device.

The three main categories are:

  • Frequency Division Multiplexing (FDM) — separate frequency bands for each channel; analogue
  • Wavelength Division Multiplexing (WDM) — FDM applied to optical fibre using different light wavelengths
  • Time Division Multiplexing (TDM) — separate time slots for each channel; digital
2 Frequency Division Multiplexing (FDM) ⌄

FDM is used when the available bandwidth of the medium exceeds the bandwidth needed by any single source. Each input signal is modulated onto a different carrier (subcarrier) frequency, producing modulated signals that are summed into a composite baseband signal, then optionally shifted to a higher transmission band.

  • Input signals may be analogue or digital (digital inputs pass through modems first)
  • Guard bands — unused frequency gaps between channels prevent interference (crosstalk)
  • At the receiver: a bandpass filter isolates each subcarrier, which is then demodulated to recover the original signal
  • The transmitted composite signal is always analogue
⚠
Exam note: Two key problems with FDM are crosstalk (overlapping spectra between channels) and intermodulation noise (amplifier non-linearities on long links inject energy into adjacent channels).
3 Wavelength Division Multiplexing (WDM) ⌄

WDM is simply FDM applied to optical fibre. Multiple laser sources each emit light at a distinct wavelength; a multiplexer (prism or diffraction grating) combines them onto a single fibre. Optical amplifiers boost all wavelengths simultaneously along the span, and a demultiplexer at the far end separates them back out.

  • Commercial systems: 160 channels × 10 Gbps each
  • Lab demonstrations: 256 channels at 39.8 Gbps each — ~10.1 Tbps total over 100 km
  • Most systems operate in the 1550 nm band (low-loss window for silica fibre)
  • Dense WDM (DWDM) — channel spacing ≤ 100 GHz; far more channels in the same fibre
4 Synchronous Time Division Multiplexing (TDM) ⌄

In synchronous TDM, time on the shared link is divided into frames. Each frame contains a fixed set of time slots, one (or more) pre-assigned to each source. Slots are transmitted whether or not the source has data — hence synchronous refers to the fixed assignment, not synchronous transmission per se.

  • Multiplexer scans input buffers (one bit or one byte per scan) and interleaves them into a composite digital stream
  • Total link rate must be ≥ sum of all input rates
  • A framing bit is added to each frame (added-digit framing) for synchronisation — typically an alternating 01010101… pattern
  • Pulse stuffing handles sources with slightly different clock rates: dummy bits are inserted to raise each source to a locally-generated clock, then removed at the demultiplexer
  • No data link protocol headers, flow control, or error control are needed across the mux link — these operate per-channel end-to-end
⚠
Exam note: If a receiver on one channel cannot accept data, the multiplexer carries on — empty slots are sent and the source must be quenched. The TDM frame rate does not slow down for any individual channel.
5 Statistical TDM (STDM) ⌄

Statistical TDM (also called asynchronous or intelligent TDM) improves on synchronous TDM by allocating slots on demand rather than pre-assigning them. The multiplexer scans input buffers and fills outgoing frames only with data that is actually waiting — empty slots are not transmitted.

  • The multiplexed line data rate can be lower than the aggregate input rate, because not all sources transmit simultaneously
  • Each slot must carry an address field (and often a length field) to identify the source — overhead per slot is higher than synchronous TDM
  • During traffic peaks, input buffers can fill; there is a tradeoff between buffer size and link data rate
  • STDM frames use HDLC-like framing: Flag | Address | Control | STDM subframe | FCS | Flag
💡
Key insight: Synchronous TDM wastes capacity on idle sources; STDM reclaims that capacity. The price is address overhead per slot and buffer management complexity.
6 DS-1 and the North American TDM hierarchy ⌄

The DS-1 format is the basis of the North American digital carrier hierarchy. It multiplexes 24 channels into a 193-bit frame (24 × 8 bits + 1 framing bit), transmitted at 1.544 Mbps (8000 frames/sec × 193 bits).

  • Voice channels: 8-bit PCM on five of every six frames; the eighth bit of each channel is "robbed" on every sixth frame to carry signalling information
  • Data service: 23 channels of user data (7 bits/channel/frame = 56 kbps each); channel 24 reserved for sync byte
  • Higher levels are formed by bit-interleaving DS-1 streams: DS-2 = 4 × DS-1 = 6.312 Mbps; DS-3 = 7 × DS-2; DS-4 = 6 × DS-3
  • International (ITU-T) hierarchy uses 30 channels per frame at 2.048 Mbps (Level 1) — incompatible with North American DS-1

ADSL & Discrete Multitone (DMT)

A ADSL — Asymmetric Digital Subscriber Line ⌄

ADSL provides high-speed digital data over existing twisted-pair telephone wire, exploiting the full 1 MHz capacity of the local loop. It is asymmetric because downstream bandwidth (network → subscriber) far exceeds upstream (subscriber → network), matching typical internet usage patterns.

  • 0–25 kHz: reserved for POTS (Plain Old Telephone Service) — ensures voice still works
  • ~25–200 kHz: upstream data channel (smaller because less demand)
  • ~250 kHz–1 MHz: downstream data channel (large — web pages, streaming)
  • Two approaches to separate up/downstream: FDM (non-overlapping bands) or echo cancellation (overlapping bands; more flexible but requires cancellation DSP at both ends)
  • Range: up to 5.5 km on 24-gauge UTP; speed degrades with distance and wire quality

B Discrete Multitone (DMT) — the ADSL modulation scheme ⌄

DMT divides the available ADSL band into 4 kHz subchannels and allocates bits to each based on its measured signal-to-noise ratio (SNR). Subchannels with good SNR carry more bits; poor or unusable subchannels carry zero.

Conceptual Q1. What is the fundamental economic argument for multiplexing? Why doesn't each device get its own dedicated line? ⌄

The cost per kbps of a transmission facility decreases as the aggregate data rate increases — high-capacity links are disproportionately cheap per bit. Most individual devices only require a modest fraction of a high-speed trunk's capacity, so sharing a single high-rate link among many low-rate sources delivers the same capacity at lower total cost than providing each device with its own dedicated connection.

Similarly, the cost of transmission and receiving equipment per kbps also falls as data rate rises, further incentivising sharing.

Conceptual Q2. Explain how FDM works. What are guard bands and why are they needed? ⌄

In FDM, each source signal is modulated onto a distinct subcarrier frequency so that all channels occupy separate frequency bands. The modulated signals are summed into a composite analogue signal and transmitted over a medium whose bandwidth exceeds the sum of all channel bandwidths.

At the receiver, a bandpass filter centred on each subcarrier isolates that channel, which is then demodulated to recover the original signal.

Guard bands are unused frequency gaps between adjacent channels. They are necessary because bandpass filters are not perfectly sharp — without gaps, the edges of one channel's spectrum would overlap with the next, causing crosstalk. Guard bands provide a buffer that allows practical (imperfect) filters to still achieve adequate channel separation.

Application Q3. Three voice signals (0–4 kHz bandwidth each) are FDM-multiplexed. Sketch the frequency allocations if subcarriers are at 64, 68, and 72 kHz and only the lower sideband of each is used. ⌄

Each voice signal has an effective spectrum of 300–3400 Hz. When modulated onto a carrier with only the lower sideband retained, the signal appears below the carrier frequency:

  • Subcarrier 64 kHz: lower sideband occupies ~60.6–63.7 kHz
  • Subcarrier 68 kHz: lower sideband occupies ~64.6–67.7 kHz
  • Subcarrier 72 kHz: lower sideband occupies ~68.6–71.7 kHz

The spectra fit neatly within the 60–72 kHz band with small gaps between channels. This is the AT&T Group FDM technique — 12 such channels occupy 60–108 kHz.

Two problems to note: (1) Crosstalk if channel spectra overlap; (2) intermodulation noise on long links with amplifiers.

Conceptual Q4. Why is synchronous TDM called "synchronous"? What problem does pulse stuffing solve? ⌄

Synchronous TDM is called "synchronous" because time slots are pre-assigned and fixed to specific sources — not because synchronous transmission is used. Each source always occupies the same slot positions in every frame, whether or not it has data to send.

Pulse stuffing solves the clock synchronisation problem. If each input source has its own independent clock, slight rate differences between clocks accumulate over time and cause misalignment — frames become corrupted. Pulse stuffing works by deliberately making the outgoing multiplexed rate slightly higher than the maximum instantaneous input rate. Dummy (stuffed) bits are inserted into each input stream to raise it to a locally-generated clock rate. These stuffed bits are inserted at known, fixed positions in the frame, so the demultiplexer can identify and remove them. The result is a properly synchronised output regardless of input clock drift.

Application Q5. A synchronous TDM multiplexer has 4 sources each at 9.6 kbps. What is the minimum link rate required? If source C is idle, what happens to its slot? ⌄

Minimum link rate = sum of input rates + framing overhead ≥ 4 × 9.6 = 38.4 kbps (plus a small fraction for framing bits). In practice, the link would be provisioned slightly above this to accommodate framing and pulse-stuffing overhead.

If source C is idle, its slot is still transmitted in every frame — it carries an empty (null) payload. The multiplexer cannot skip the slot because the demultiplexer relies on positional identity to route data: removing slot C would shift all subsequent slots and destroy synchronisation. Source C must be quenched (told to stop generating data) at the application level. The wasted capacity is the core inefficiency of synchronous TDM.

Conceptual Q7. Describe the DS-1 frame format. How is the 1.544 Mbps data rate derived? ⌄

A DS-1 frame contains 24 channels × 8 bits + 1 framing bit = 193 bits per frame. The framing bit allows the receiver to identify frame boundaries.

Frames are transmitted at 8000 frames per second (required to sample voice at twice the 4 kHz Nyquist rate for PCM).

Data rate = 193 bits × 8000 frames/sec = 1.544 Mbps.

For voice: five of every six frames use full 8-bit PCM per channel; on every sixth frame the eighth bit of each channel is "robbed" for signalling (e.g. on-hook/off-hook), giving effectively 7-bit audio. For 56 kbps data service: 7 bits/channel × 8000 frames/sec = 56 kbps per channel.

Compare Q8. How is WDM related to FDM? What makes DWDM "dense"? ⌄

WDM is conceptually identical to FDM — multiple channels share a medium by occupying separate "frequency" bands simultaneously. The distinction is purely the medium and scale: WDM operates on optical fibre using different light wavelengths (typically in the 1550 nm band), whereas conventional FDM operates at radio and lower frequencies on copper or coaxial media.

The architecture is the same: a multiplexer (prism or diffraction grating) combines the wavelengths, optical amplifiers boost all channels simultaneously along the fibre, and a demultiplexer at the far end separates them.

DWDM (Dense WDM) simply means the wavelength (frequency) spacing between channels is very small — typically ≤ 100 GHz (ITU-T G.692). Tighter spacing allows far more channels in the same fibre, increasing total capacity enormously. There is no official threshold; it connotes more channels and closer spacing than basic WDM.

Application Q9. Explain how ADSL uses FDM to coexist with voice on the same wire. Why is it asymmetric? ⌄

ADSL exploits the fact that telephone-grade twisted pair can carry signals up to ~1 MHz — far beyond the 4 kHz voice band. FDM divides this bandwidth:

  • 0–25 kHz: POTS voice (0–4 kHz used; extra bandwidth prevents crosstalk into data)
  • ~25–200 kHz: upstream data (subscriber → network)
  • ~250 kHz–1 MHz: downstream data (network → subscriber)

The downstream channel is much wider because internet usage is asymmetric — users download far more than they upload (web pages, video, files). Allocating more bandwidth downstream matches this demand. The upstream channel is smaller because only requests and uploads travel that direction.

Within each band, ADSL uses DMT modulation — dividing the band into 4 kHz subchannels and assigning bits to each based on measured SNR. This adapts to the actual quality of the specific wire, maximising throughput.

Conceptual Q10. A TDM link does not use data link control headers or flow control. Explain why not, and how error control is handled. ⌄

No headers or trailers: The TDM frame has no need for source/destination address fields — the slot position uniquely identifies the channel. There are no packets to frame; the structure is implicit.

No flow control: The multiplexed line rate is fixed. All slots must be filled at the predetermined rate regardless of what any one source is doing. If a receiver on one channel cannot accept data, the corresponding source is quenched at the application level and empty slots are sent — the mux cannot pause the entire frame for one channel.

Error control: Errors are detected and handled on an individual per-channel basis. Each end-to-end session running over its channel implements its own data link or transport protocol (e.g. HDLC per channel). Requesting retransmission of an entire TDM frame because of an error on one channel would be wrong — the other channels' data is fine. So error control is applied per channel, independently of the multiplexer.

01 — Core concepts

Topic summaries

1 Switched networks — the big picture ⌄

For data transmission beyond a local area, data travels from source to destination through a network of intermediate switching nodes. These nodes are not concerned with the content of the data — they simply move it from node to node until it reaches its destination.

  • Stations — end devices attached to the network (computers, terminals, telephones)
  • Nodes — switching devices forming the network fabric, connected by transmission links
  • Node-station links are generally dedicated point-to-point; node-node links are typically multiplexed (FDM or TDM)
  • Networks are usually partially connected — more than one path between any pair of stations improves reliability

There are two fundamental switching technologies: circuit switching and packet switching.

2 Circuit switching ⌄

Circuit switching establishes a dedicated path between two stations before any data is transferred. Resources along the entire path are reserved for the exclusive use of that connection. There are three phases:

  • Circuit establishment — an end-to-end circuit is set up through the network; each node allocates a dedicated channel on each link
  • Data transfer — once established, the connection is transparent; data flows as if a direct link exists (analog or digital)
  • Circuit disconnect — one station terminates the connection; signals propagate to free reserved resources

Circuit switching is inefficient for data: capacity is reserved for the duration of the connection even when no data is being sent. However, once the circuit is established, there is no further delay — the network appears transparent to the user.

⚠
Key exam point: Circuit switching was designed for voice, where channels are continuously active. For bursty data traffic (e.g. web browsing), most of the reserved bandwidth sits idle — this is the core inefficiency.
3 Packet switching — advantages ⌄

Packet switching was designed for bursty data traffic. Stations divide data into small packets, each containing user data plus control information (including routing addresses). Packets are received, briefly stored (buffered), and forwarded node-by-node.

  • Line efficiency — a single node-to-node link is dynamically shared by many packets. No capacity is pre-allocated and wasted
  • Data-rate conversion — two stations with different data rates can exchange packets because each connects to its local node at its own speed; nodes buffer as needed
  • Resilience under load — when a circuit-switching network is congested it refuses new connections; packet networks continue accepting packets (delivery delay increases instead)
  • Priority queuing — nodes can transmit higher-priority packets first, giving preferential treatment to critical traffic
4 Datagram vs virtual circuit ⌄

Packet switching has two internal approaches to routing packets through the network:

  • Datagram — each packet is treated independently. Even packets from the same message may take different routes to the destination. Switches (routers) are connectionless — no setup phase, no state information maintained per connection. Packets may arrive out of order or be lost; upper-layer protocols handle reordering and recovery. More robust against node failure.
  • Virtual circuit — a preplanned route is established before any packets are sent. All packets for that connection follow the same route. Setup and teardown phases exist (like circuit switching), but data is packetized (like datagram). Each packet carries a local virtual circuit identifier, not a full end-to-end address. The network can provide sequencing and error control, and packets are forwarded more quickly since routing decisions were made at setup time.
💡
Virtual circuit vs circuit switching: Both have a setup phase, but virtual circuits still packetize data and share link capacity. The "circuit" is logical, not dedicated physical bandwidth. Virtual circuits are implemented at the data-link layer; datagrams at the network layer.
5 Packet size and performance ⌄

There is a significant relationship between packet size and transmission time. With store-and-forward switching, a node must receive an entire packet before forwarding it.

  • Breaking a long message into smaller packets allows pipelining: the first packet can be forwarded from node A to node B while the second packet is still being received at node A from the source
  • This reduces total transmission delay — with 2 intermediate nodes and 2 packets, delay falls from 3× single-packet time to 2.5×
  • However, very small packets become counterproductive: each packet carries a fixed header overhead, so more packets = more header bytes relative to user data. Processing and queuing delays also increase.
  • ATM's 53-octet fixed-size cell is a carefully chosen compromise
6 Performance: propagation, transmission, and node delay ⌄

Three types of delay affect network performance:

  • Propagation delay — time for a signal to travel from one node to the next. Generally negligible (~2 × 10⁸ m/s in copper)
  • Transmission time — time to put all bits of a block onto the link. A 10,000-bit block on a 10 kbps link takes 1 second
  • Node delay — processing time at a node to switch and forward the data

For circuit switching there is a one-time setup delay, then near-zero node delay during transfer (the path is transparent). For packet switching, each node introduces store-and-forward delay but there is no setup overhead for small transfers.

03 — Packet-switching interfaces

X.25 & Frame Relay

A X.25 — the traditional packet-switching interface ⌄

X.25 is an ITU-T standard defining the interface between a host system (DTE) and a packet-switching network (DCE). It defines three levels:

  • Physical (X.21) — governs the physical interface between DTE (Data Terminal Equipment, the user's device) and DCE (Data Circuit-terminating Equipment, the network node). Can substitute EIA-232.
  • Link (LAPB) — Link Access Protocol Balanced, a subset of HDLC. Provides reliable transfer of data across the physical link as a sequence of frames, with error and flow control.
  • Packet level — provides virtual circuit (VC) service. Subscribers set up logical connections called external virtual circuits. Sequence numbers P(S) and P(R) enable flow and error control per VC.

The key issues with X.25: it carries call control packets in-band, multiplexes virtual circuits at layer 3, and performs flow and error control at both layers 2 and 3. This considerable overhead was acceptable for unreliable analog networks but becomes a bottleneck on modern reliable digital links.

B Frame Relay — streamlined packet switching ⌄

Frame Relay was designed to eliminate most of X.25's overhead for use over reliable modern digital networks. Key differences from X.25:

  • Call control in a separate logical connection — intermediate nodes need not maintain per-connection state tables for signalling
  • Multiplexing and switching at layer 2 — eliminates one entire layer of processing vs X.25's layer 3 multiplexing
  • No hop-by-hop flow or error control — end-to-end control is delegated to higher layers. A frame in error is simply discarded.

The user data frame format (LAPF core) has no Control field — only one frame type exists, carrying user data. The Address field carries a DLCI (Data Link Connection Identifier) with local significance only. No sequence numbers means no flow or error control — but throughput improvements over X.25 of an order of magnitude are possible. Frame Relay supports speeds up to 2 Mbps and beyond.

⚠
Exam note: Frame Relay's loss of hop-by-hop error control is not a major disadvantage because modern digital links are highly reliable. The performance gain (lower delay, higher throughput) outweighs this for most applications.

04 — Asynchronous Transfer Mode

ATM — architecture & logical connections

1 What is ATM? ⌄

ATM (Asynchronous Transfer Mode), also called cell relay, is a streamlined packet-transfer interface that takes advantage of reliable modern digital facilities to provide faster packet switching than X.25.

  • Like packet switching, ATM transfers data in discrete chunks and multiplexes multiple logical connections over a single physical interface
  • Unlike variable-length packets, ATM uses fixed-size cells (53 bytes: 5-byte header + 48-byte payload)
  • Minimal error and flow control — reduces per-cell processing overhead and enables very high data rates
  • Physical layer data rates: 25.6 Mbps to 622.08 Mbps

The fixed cell size simplifies switching hardware — cells can be switched entirely in hardware rather than software, which is critical at these speeds.

2 ATM protocol architecture & reference model planes ⌄

The ITU-T ATM protocol architecture has three planes of operation:

  • User plane — provides user information transfer, along with associated flow and error control
  • Control plane — performs call control and connection control functions
  • Management plane — plane management (whole-system coordination) and layer management (resources within protocol entities)

Two ATM-specific protocol layers sit above the physical layer:

  • ATM layer — common to all services; defines fixed-size cell transmission and logical connection usage
  • ATM Adaptation Layer (AAL) — service-dependent; maps higher-layer information into ATM cells and reassembles cells back at the receiver
3 Virtual Channel Connections (VCC) and Virtual Path Connections (VPC) ⌄

ATM uses a two-level hierarchy of logical connections:

  • Virtual Channel Connection (VCC) — the basic unit of switching in ATM, analogous to a virtual circuit in X.25. A VCC is a full-duplex, variable-rate flow of fixed-size cells between two endpoints. Cell sequence integrity is preserved within a VCC.
  • Virtual Path Connection (VPC) — a bundle of VCCs that share the same endpoints. All cells on all VCCs within a VPC are switched together as a unit.

The virtual path concept was developed to manage the increasing proportion of control costs in high-speed networks. By grouping connections into virtual paths, network management actions apply to a small number of groups rather than thousands of individual VCCs.

Advantages of virtual paths:

  • Simplified network architecture — separates per-channel and per-group transport functions
  • Increased performance and reliability — fewer aggregated entities to manage
  • Reduced processing and short setup time — new VCCs within an existing VPC require only endpoint processing, no transit node call processing
  • Enhanced services — VPCs are visible to end users (e.g. closed user groups)
4 VCC uses and characteristics ⌄

VCCs can be established between three types of endpoint pairs:

  • Between end users — carries user data and/or control signalling. The VPC provides overall capacity; VCC organisation within it is the users' responsibility.
  • Between end user and network — used for user-to-network control signalling
  • Between network entities — used for network traffic management and routing

ITU-T I.150 lists key VCC/VPC characteristics: quality of service (cell loss ratio, delay variation), switched and semipermanent connections, cell sequence integrity, and traffic parameter negotiation (peak rate, average rate, burstiness).

5 Control signalling in ATM ⌄

ATM requires mechanisms to establish and release VCCs and VPCs on separate connections from the ones being managed. For VCCs, four methods are defined:

  • Semipermanent VCC — pre-configured by agreement; no control signalling required
  • Meta-signalling channel — a permanent low-rate channel used to set up signalling channels
  • User-to-network signalling VCC — set up via meta-signalling; used to establish user data VCCs
  • User-to-user signalling VCC — allows two end users to establish/release VCCs without network intervention, within a pre-established VPC

For VPCs, three methods: semipermanent, customer-controlled (via signalling VCC), or network-controlled (for network management).

Key terms & definitions

Circuit switching
A dedicated communication path is established end-to-end before data transfer. Resources are reserved for the duration and released on disconnect. Transparent to users once established.
Packet switching
Data divided into packets, each routed independently (datagram) or along a pre-set path (virtual circuit). Links are shared dynamically — no reserved bandwidth.
Datagram
A packet-switching mode where each packet is treated independently with a full destination address. No setup phase. Packets may arrive out of order or by different routes. More resilient but upper layers must reorder.
Virtual circuit (VC)
A logical connection established by a setup phase. All packets follow the same route; each carries a local VC identifier, not a full address. Sequence preserved. Can be internal (network) or external (user-visible).
X.25
ITU-T standard for the interface between a host and a packet-switching network. Defines three levels: Physical (X.21), Link (LAPB), and Packet (virtual circuit service). High overhead due to per-hop error and flow control.
Frame Relay
Streamlined packet-switching service. Eliminates X.25 overhead by using a separate connection for call control, multiplexing at layer 2, and delegating error/flow control to higher layers.
DLCI
Data Link Connection Identifier — the Frame Relay equivalent of a virtual circuit number. Has local significance only; the network maps DLCIs between link segments.
ATM (cell relay)
Asynchronous Transfer Mode. Fixed 53-byte cells, minimal error/flow control, virtual-circuit based. Designed for high-speed (25.6–622 Mbps) unified voice/video/data networks.
VCC
Virtual Channel Connection — the basic switching unit in ATM. A full-duplex logical connection between two endpoints; cell sequence integrity is preserved within a VCC.
VPC
Virtual Path Connection — a bundle of VCCs with the same endpoints, switched as a group. Reduces control costs by treating many channels as a single entity.
AAL
ATM Adaptation Layer — service-dependent layer above the ATM layer. Maps higher-layer protocol data into 48-byte cell payloads (segmentation) and reassembles them at the destination.
HEC
Header Error Control — 8-bit CRC field in the ATM cell header. Provides single-bit error correction and multi-bit error detection, and is used for cell boundary synchronisation.
CBR
Constant Bit Rate — ATM service category for applications requiring a fixed, continuously available data rate with tight delay bounds (e.g. uncompressed voice/video).
ABR
Available Bit Rate — ATM service with minimum (MCR) and peak (PCR) rate parameters. Unused network capacity is shared fairly among ABR sources using explicit congestion feedback.
UBR
Unspecified Bit Rate — ATM best-effort service. Cells forwarded FIFO on spare capacity with no commitment and no congestion feedback. Suited to delay-tolerant TCP-based traffic.

A node must receive an entire packet/cell before forwarding it. Introduces per-hop transmission delay but allows error checking before forwarding.

Conceptual Q1. Why is circuit switching considered inefficient for data communication? How does packet switching address this? ⌄

Circuit switching inefficiency: Once a circuit is established, bandwidth is reserved on every link in the path for the entire duration of the connection — even when no data is being transmitted. For voice, utilisation may be 40–60%; for typical bursty data (web browsing, file transfers), the channel is idle most of the time. This is wasteful of a shared resource.

Packet switching solution: Links are shared dynamically. Packets from many different connections are interleaved (statistical multiplexing). A link is only occupied while a packet is actually being transmitted; it is immediately available for packets from other connections. There is no reserved bandwidth — the link can run at near full utilisation across many simultaneous users.

Conceptual Q3. What are the three layers of X.25, and what does each provide? ⌄
  • Physical level (X.21 or EIA-232) — governs the physical interface between DTE (user equipment) and DCE (network node). Defines electrical characteristics and signalling for the point-to-point link.
  • Link level (LAPB) — Link Access Protocol Balanced, a subset of HDLC. Provides reliable, error-controlled data transfer across the physical link as a sequence of frames. Handles frame delimiting, error detection, and retransmission.
  • Packet level — provides the virtual circuit service (external virtual circuits). Multiplexes multiple VCs over the link. Uses sequence numbers P(S) and P(R) for per-VC flow and error control.
Compare Q4. What are the key differences between X.25 and Frame Relay? Why is Frame Relay faster? ⌄

Three key differences:

  • Call control signalling — X.25 carries it in-band (same virtual circuit as data); Frame Relay uses a separate permanent connection, so intermediate nodes don't maintain per-connection state for signalling.
  • Multiplexing layer — X.25 multiplexes at layer 3 (Packet); Frame Relay multiplexes at layer 2, eliminating an entire layer of processing at every intermediate node.
  • Hop-by-hop error/flow control — X.25 performs this at every node (both layers 2 and 3); Frame Relay eliminates it entirely, delegating end-to-end control to higher layers.

Frame Relay is faster because each intermediate node does far less work — it just checks the frame for errors (discarding if found), reads the DLCI, and forwards. Studies show throughput improvements of an order of magnitude over X.25.

Conceptual Q5. Describe the structure of an ATM cell. Why is the cell size fixed at 53 bytes? ⌄

An ATM cell is always 53 bytes: a 5-byte header and a 48-byte information payload.

The header contains (at the UNI): GFC (4 bits), VPI (8 bits), VCI (16 bits), PT (3 bits), CLP (1 bit), and HEC (8 bits).

Why fixed size?

  • Hardware switching — fixed size allows the switching function to be implemented entirely in hardware (ASICs) rather than software, enabling operation at Gbps line rates
  • Reduced queuing delay — a high-priority cell arriving just behind a lower-priority cell waits at most one cell-transmission time. With variable-length packets, a small cell could wait behind a large frame.
  • Predictable timing — fixed size simplifies delay calculation and QoS guarantees for real-time traffic

The 53-byte compromise (rather than, say, 32 or 64 bytes) balanced voice delay requirements against data efficiency: the 5-byte header represents about 10% overhead on a 48-byte payload.

Conceptual Q6. Explain the relationship between a VCC and a VPC in ATM. Why was the VPC concept introduced? ⌄

A VCC (Virtual Channel Connection) is the basic ATM connection — analogous to a virtual circuit. It carries a cell stream between two endpoints with preserved sequence.

A VPC (Virtual Path Connection) is a bundle of VCCs that share the same two endpoints. All cells on all VCCs within a VPC carry the same VPI and are switched together as a single group through the network.

Why VPCs? In high-speed networks, the cost of managing connections (control signalling, state tables, monitoring) becomes an increasingly large proportion of total network cost. By grouping many VCCs into a VPC:

  • Network management actions apply to the group, not individual channels — far fewer entities to track
  • New VCCs can be added to an existing VPC with only endpoint processing — no call processing at transit nodes
  • Performance and reliability improve as the network deals with fewer, aggregated entities
Application Q7. Explain the purpose of each ATM header field: VPI, VCI, CLP, and HEC. ⌄
  • VPI (Virtual Path Identifier) — identifies the virtual path. All VCCs sharing the same VPC carry the same VPI. Switching nodes can route the cell based on VPI alone when operating at the virtual path level.
  • VCI (Virtual Channel Identifier) — identifies the specific virtual channel within the virtual path. VPI + VCI together uniquely identify a connection at each node. Each node maintains a table mapping incoming (VPI, VCI) → outgoing (VPI, VCI) and interface.
  • CLP (Cell Loss Priority) — 1 bit. A value of 0 means the cell should not be discarded unless there is no other option; 1 means the cell may be discarded by the network if congestion demands it. End users or the network can set this bit to mark lower-priority excess traffic.
  • HEC (Header Error Control) — 8-bit CRC over the 5-byte header. Corrects single-bit errors and detects multi-bit errors. Also used for cell boundary synchronisation at the physical layer — the receiver uses the known header pattern to identify cell boundaries in the bit stream.

Application Q9. Explain how packet size affects end-to-end delay through a store-and-forward network. What is the optimal strategy and its limit? ⌄

In a store-and-forward network, a node must receive the entire packet before it begins forwarding. For a message passing through two intermediate nodes (X → A → B → Y):

  • One large packet of M bytes: total delay = 3 × (transmission time for M bytes) = 3M time units
  • Two packets of M/2 bytes each: node A can forward the first packet while still receiving the second → total delay = 2.5M time units (pipelining saves one packet-transmission time)
  • k packets of M/k bytes: pipelining reduces delay further

The limit: very small packets become counterproductive. Each packet carries a fixed header (e.g. 3 bytes for a simple example). More, smaller packets mean more header overhead relative to user data, and more processing and queuing delay at each node. The optimal packet size balances pipelining gains against header overhead — which is why ATM chose 53 bytes as a carefully engineered compromise.

Conceptual Q10. What is the difference between an external virtual circuit and an internal virtual circuit in X.25? How does ATM's VCC relate to these concepts? ⌄

Internal virtual circuit (X.25 packet level): a specific preplanned physical route through the network between two nodes, established inside the network. It is the actual path used to carry packets.

External virtual circuit (X.25 packet level): the logical connection visible to subscribers — a persistent logical channel between two end systems identified by a virtual circuit number. All data associated with that number forms a single stream.

Typically there is a one-to-one mapping between external and internal virtual circuits. However, X.25 can also operate with a datagram-style internal network while still presenting external virtual circuits to subscribers.

ATM VCC: directly analogous to an X.25 external virtual circuit — a logical connection between endpoints identified by the VPI/VCI pair. The network routes cells internally based on VPI/VCI, switching tables at each node. The VCC provides the subscriber with a logical channel, while the internal routing is transparent. ATM extends this concept with the VPC (a bundle of VCCs) to reduce control overhead — an abstraction X.25 does not have.

01 — Core concepts

Topic summaries

1 Principles of cellular networks ⌄

Cellular systems were developed to increase the capacity available for mobile radio telephone service. Before cellular radio, mobile service relied on a single high-powered transmitter/receiver covering a large area — typically ~25 channels over an 80 km radius. This severely limited the number of simultaneous users.

The cellular approach replaces one big transmitter with many low-power transmitters, each covering a smaller cell. The same frequencies can be reused in cells far enough apart that co-channel interference is acceptable, dramatically increasing total capacity.

2 Cellular network organisation ⌄

A geographic area is divided into cells arranged in a tiling pattern to provide full coverage. Each cell has:

  • Its own antenna and allocated frequency range
  • A base station (BS) — transmitter, receiver, and control unit

Adjacent cells use different frequencies to avoid interference (crosstalk). Cells sufficiently distant can reuse the same frequency band. In practice, hexagonal cells are the theoretical ideal because all six neighbours are equidistant from the centre, giving uniform coverage with no gaps.

The system hierarchy: mobile unit ↔ Base Transceiver Station ↔ Base Station Controller ↔ Mobile Telecommunications Switching Office (MTSO) ↔ Public Switched Telephone Network (PSTN).

3 Frequency reuse ⌄

Frequency reuse is the central capacity mechanism of cellular systems. Each cell is allocated 10–50 frequencies. The same frequencies are reused across the network in cells that are far enough apart that signals do not interfere.

  • The reuse factor N is the number of cells in a cluster before frequencies repeat (e.g. N = 4, 7, 19)
  • Larger N → more separation between co-channel cells → less interference, but fewer frequencies per cell
  • Smaller N → more frequencies per cell → higher capacity, but greater co-channel interference risk

The power of the base transceiver is carefully controlled to allow communications within the cell while limiting signal escape to adjacent cells.

⚠
Exam note: Co-channel interference occurs when cells using the same frequency are too close together. The minimum separation distance D depends on the reuse factor N and cell radius R: the larger N is, the greater D/R must be.
4 Cellular system channels & call operations ⌄

Two types of channels operate between a mobile unit and its base station:

  • Control channels — used to set up and maintain calls; establish the relationship between a mobile unit and the nearest base station
  • Traffic channels — carry voice and data once a call is established

Key call operations managed by the MTSO:

  • Call setup — mobile monitors for strongest control channel signal; sends connection request; MTSO pages cells; call accepted on a traffic channel
  • Handoff (handover) — as a mobile moves, the MTSO reassigns the call to the BS with the strongest signal, switching traffic channels transparently
  • Call blocking — if all traffic channels are busy after repeated attempts, a busy tone is returned
  • Call drop — when the BS can no longer maintain the required signal strength
5 Mobile radio propagation effects ⌄

Two key impairments affect wireless channels:

  • Signal strength — must be strong enough for quality communications but not so strong as to cause co-channel interference. Path loss is predicted empirically using models such as the Okumura–Hata model (derived from measurements in Tokyo).
  • Fading — time variation of the received signal caused by changes in the transmission path. Even within the acceptable signal-strength range, propagation effects can disrupt the signal.

Three fundamental propagation mechanisms cause fading:

  • Reflection (R) — signal bounces off large surfaces (buildings, ground)
  • Scattering (S) — signal scattered by small objects (lamp posts, signs)
  • Diffraction (D) — signal bends around obstructions

Multipath propagation — signals arriving via multiple paths — causes the received signal to consist of a LOS (line-of-sight) pulse plus delayed multipath copies, leading to intersymbol interference.

6 Error compensation mechanisms ⌄

Three techniques combat the effects of fading and noise in mobile systems:

  • Forward Error Correction (FEC) — applicable in digital transmission. Redundant bits are sent so the receiver can correct errors without retransmission. The total bits sent / data bits ratio is typically 2–3×.
  • Adaptive Equalization — combats intersymbol interference by gathering dispersed symbol energy back into its original time interval. Applied to both analogue and digital transmissions.
  • Diversity — based on the fact that independent channels experience independent fading events. Multiple logical channels carry parts of the signal; errors are reduced (not eliminated). Space diversity uses physically separate paths; frequency and time diversity are more common. Spread spectrum is the most important example of frequency diversity.

04 — Propagation impairments

Types of fading

Fast fading

Rapid variations in signal strength occurring over very short distances — about one-half a wavelength (a few centimetres at typical mobile frequencies). Caused by constructive and destructive interference of multipath signals as the mobile moves. Also called Rayleigh fading or short-term fading.

Slow fading

Change in the average received power level as the user moves through different terrain — passing buildings of different heights, vacant lots, intersections. The signal envelope varies over distances comparable to the size of obstacles. Also called shadowing or log-normal fading.

Flat fading

All frequency components of the received signal fluctuate in the same proportions simultaneously. The channel bandwidth is much wider than the signal bandwidth, so no frequency-selective distortion occurs. The entire signal fades together — amplitude changes but shape is preserved.

Selective fading

Attenuation occurring over only a portion of the signal bandwidth. When the channel coherence bandwidth is narrower than the signal bandwidth, different frequency components fade independently. Causes signal distortion and intersymbol interference. The dominant problem at higher data rates.

💡
Classifying fading — two independent axes: Fading is classified separately as fast/slow (relates to how quickly the channel changes relative to the symbol period) AND as flat/selective (relates to how the channel varies across the signal bandwidth). A signal can simultaneously be, for example, slow and frequency-selective.

C Key technologies: OFDM and MIMO ⌄

OFDM (Orthogonal Frequency-Division Multiplexing) divides the available bandwidth into many narrow orthogonal subcarriers. Benefits: highly resistant to multipath and frequency-selective fading; efficient use of spectrum. Drawback: high peak-to-average power ratio (PAPR), requiring linear power amplifiers — bad for battery-operated handsets. LTE-Advanced uses SC-FDMA on the uplink to reduce PAPR.

MIMO (Multiple-Input Multiple-Output) uses multiple antennas at both transmitter and receiver. Benefits: spatial multiplexing increases data rate (sending parallel streams); diversity gain improves reliability. LTE-Advanced supports up to 8×8 MIMO on the downlink.

Two 4G standardisation candidates emerged: LTE-Advanced (from 3GPP, consortium of North American, Asian, and European standards organisations) and WiMAX (from IEEE 802.16). LTE-Advanced became the dominant global standard.

D Femtocells ⌄

A femtocell is a low-power, short-range, self-contained base station — typically for home or small enterprise use. It connects to the operator's network via the user's existing DSL or FTTH broadband (IP backhaul) rather than requiring a dedicated wireless backhaul link.

Key attributes:

  • IP backhaul — uses internet connection rather than dedicated wireless link
  • Self-optimisation — automatically configures its frequency, power, and neighbour list
  • Low power consumption and ease of deployment (plug-and-play)

Femtocells now outnumber macrocells globally — they are by far the most numerous type of small cell. The term has expanded to cover higher-capacity units for enterprise, rural, and metropolitan deployments. A femtocell gateway in the operator's core network connects the femtocell access points to the macrocell system.

⚠
OFDMA vs SC-FDMA: LTE uses OFDMA on the downlink (base station → mobile) because the base station can afford the power amplifier inefficiency. It uses SC-FDMA on the uplink (mobile → base station) to preserve battery life — the key trade-off is spectral efficiency vs PAPR.

Interference between two cells using the same frequency band when they are too close together. Minimised by choosing an appropriate reuse factor N.
Cell splitting
Subdividing a busy cell into smaller cells (each with its own BS) to increase capacity. Halving radius gives four times the cell density.

Dividing a cell into 3–6 wedge-shaped sectors using directional antennas, each with its own frequency subset, to reduce co-channel interference.
Fading
Time variation of received signal strength caused by changes in the propagation path. Classified as fast/slow (time domain) and flat/selective (frequency domain).
Multipath propagation
Signal reaching the receiver via multiple paths (LOS + reflections/scattering/diffraction). Causes fast fading and, at high data rates, intersymbol interference.

MIMO

Practice Q&A

Conceptual Q1. What was the fundamental limitation of pre-cellular mobile radio, and how does the cellular concept overcome it? ⌄

Pre-cellular mobile radio used a single high-powered transmitter/receiver covering an entire metropolitan area — typically only ~25 channels over an 80 km radius. This hard-caps the number of simultaneous users across the entire coverage area.

The cellular concept overcomes this by replacing the single transmitter with many low-power base stations, each covering a small cell. The same frequencies can be reused in geographically distant cells. If a city is divided into N cells, and each cell can support 25 channels, total capacity is 25 × (number of cells). Capacity scales with the number of cells, not with spectrum.

Conceptual Q2. Why are hexagons preferred over squares for modelling cell geometry? ⌄

Both hexagons and squares tile a plane with no gaps. However, hexagons are preferred because all six adjacent cells are equidistant from the centre cell — distance d to each neighbour is identical. Squares have two classes of neighbour: four edge-adjacent (distance d) and four corner-adjacent (distance 1.41d). This asymmetry makes frequency planning inconsistent — corner-adjacent cells using the same frequency experience less separation, creating unequal interference.

Hexagons therefore give a uniform, predictable interference environment and are the theoretical optimum for cellular planning.

Conceptual Q5. Describe the three fundamental propagation mechanisms. How does multipath propagation lead to intersymbol interference? ⌄

The three mechanisms are:

  • Reflection (R) — signal bounces off large flat surfaces such as buildings, walls, and the ground
  • Scattering (S) — signal scattered by objects small relative to the wavelength (lamp posts, signs, foliage)
  • Diffraction (D) — signal bends around obstacles such as building edges, allowing coverage in shadowed regions

Multipath propagation means the receiver sees the transmitted pulse as a direct LOS component plus multiple delayed copies arriving via different paths. At high data rates, if the symbol period T is shorter than the maximum path delay spread, delayed copies of symbol N overlap in time with symbol N+1. This is intersymbol interference (ISI). Adaptive equalization is used to cancel ISI by gathering dispersed symbol energy back into its original time interval.

Conceptual Q6. Distinguish between fast fading and slow fading. Which type is more damaging to a moving pedestrian vs a stationary user? ⌄

Fast fading: rapid fluctuations in signal strength over distances of approximately half a wavelength (a few centimetres). Caused by constructive/destructive interference of multipath signals as the mobile moves. Very relevant to a pedestrian — even slow walking covers many wavelengths per second.

Slow fading: gradual change in average received power level as the mobile passes through areas of different terrain and obstacle density (shadowing). Relevant over tens or hundreds of metres of movement.

A moving pedestrian experiences both: fast fading continuously as they walk through the multipath interference pattern, and slow fading as they move around buildings. A stationary user experiences primarily slow fading (environmental changes cause channel drift over time) and may experience fast fading due to movement of nearby objects (vehicles, people), but at a much lower rate.

Compare Q7. What are the four key differences introduced by 2G compared to 1G? ⌄
  1. Digital traffic channels — voice is encoded digitally rather than modulated as an analogue waveform, enabling compression and higher spectral efficiency
  2. Encryption — the digital signal can be encrypted over the air interface, which analogue 1G cannot do
  3. Error detection and correction — digital coding allows channel errors to be detected and corrected at the receiver
  4. New channel access methods — TDMA (multiple users share a single frequency by time-division) and CDMA (users share frequency using unique codes), replacing 1G's pure FDMA
Application Q8. Why is CDMA dominant in 3G systems? What role does the chip rate play? ⌄

CDMA is dominant in 3G because it naturally supports the variable data rate requirements of multimedia services (voice at 12 kbps, video at 384 kbps, office data at 2 Mbps) through multirate operation — different logical channels carry different data rates, and channel traffic can be switched independently to different destinations.

The chip rate is the rate at which the spreading code is transmitted (in chips per second, Mcps). For a given available bandwidth, the chip rate is determined by the desired data rate, the need for error-control overhead, and bandwidth constraints. A chip rate of 3 Mcps or higher is typical for 3G CDMA, using a 5 MHz channel — wide enough to support 144 kbps (high-mobility) and 384 kbps (pedestrian) service categories. The chip rate directly determines the processing gain (spreading factor), which sets the interference rejection capability.

Application Q9. Why does LTE use OFDMA on the downlink but SC-FDMA on the uplink? ⌄

OFDM/OFDMA has a high peak-to-average power ratio (PAPR). This requires a highly linear power amplifier, which operates with low overall power efficiency. At the base station (downlink transmitter), this is acceptable — the BS is mains-powered and its amplifier cost/efficiency is manageable.

At the mobile handset (uplink transmitter), a high-PAPR waveform would drain the battery rapidly. SC-FDMA (Single-Carrier FDMA) retains the multicarrier scheduling flexibility of OFDMA (sub-channel allocation per user) while transmitting with a single-carrier waveform at any instant — substantially lower PAPR. This makes it far more suitable for battery-operated handsets, at a modest cost in spectral efficiency compared to pure OFDMA.

Conceptual Q10. What is a femtocell, and why have femtocells come to outnumber macrocells globally? ⌄

A femtocell is a low-power, short-range, self-contained base station — typically covering a home or small office with a radius of a few metres. Unlike a macrocell (radius of several km), it connects to the operator's core network via an ordinary DSL or FTTH broadband line (IP backhaul), not a dedicated wireless or fibre backhaul.

Femtocells outnumber macrocells because:

  • Low cost and ease of deployment — plug-and-play, no site acquisition or costly backhaul
  • Indoor coverage problem — a large fraction of mobile traffic originates indoors, where macrocells provide poor penetration; femtocells solve this directly
  • Self-optimisation — automatically configure frequency and power, reducing operator management overhead
  • Capacity offload — move indoor traffic off the congested macrocell network onto the user's own broadband

01 — Core concepts

Topic summaries

1 What is a LAN? ⌄

A Local Area Network (LAN) consists of a shared transmission medium and a set of hardware and software for interfacing devices and regulating orderly access to that medium.

Key characteristics that distinguish LANs:

  • Geographically limited — typically a single building or cluster of buildings
  • High data rates compared to WANs
  • Usually privately owned — organisation controls its own network
  • Low error rate due to short distances and controlled environment
2 LAN applications ⌄

LANs serve several distinct application types, each with different requirements:

  • Personal computer LANs — low cost, moderate data rates; ubiquitous in all organisations. Attachment cost must be lower than the cost of the attached device. Support client/server applications.
  • Backend networks — interconnect large systems (mainframes, supercomputers, mass storage). Key requirements: high data rate, high-speed interface, distributed access, limited distance, limited number of devices, high reliability.
  • Storage Area Networks (SANs) — a separate network handling only storage needs. Detaches storage tasks from specific servers; storage devices (hard disks, tape libraries, CD arrays) connect directly to the network via high-speed links (typically Fibre Channel). No server sits between the storage device and the network.
  • High-speed office networks — required by desktop image processing and high-capacity local storage which overwhelm older 10 Mbps limits.
  • Backbone LANs — interconnect lower-speed departmental LANs across a premises. A high-capacity backbone handles inter-LAN traffic without replacing each local LAN.
3 LAN architecture — key elements ⌄

Four key elements define a LAN's cost, capacity, data types, efficiency, and supported applications:

  • Topology — the physical/logical arrangement of stations (bus, tree, ring, star)
  • Transmission medium — the physical channel carrying signals (twisted pair, coax, optical fibre)
  • Layout — how the medium is physically wired through a building
  • Medium Access Control (MAC) — the rules governing which station may transmit at any given time
4 Medium Access Control (MAC) — where and how ⌄

MAC determines how stations share the transmission medium. Two dimensions:

  • Where — centralised (a controller grants permission; simpler station logic, single point of failure) or distributed (stations collectively decide; more complex, more resilient)
  • How — synchronous (capacity dedicated per connection; wasteful for bursty LAN traffic) or asynchronous (demand-driven allocation)

Asynchronous techniques are divided into three categories:

  • Round robin — each station given a turn to transmit; efficient for roughly equal loads
  • Reservation — time slots reserved in advance; best for continuous stream traffic
  • Contention — all stations compete; simple, efficient under light load, but tends to collapse under heavy load. Used by Ethernet (CSMA/CD).
5 Logical Link Control (LLC) ⌄

LLC is the upper sublayer of the IEEE 802 data link layer. It is modelled on HDLC and provides a common interface above the varying MAC options. Three service types:

  • Type 1 — Unacknowledged connectionless: Uses unnumbered information (UI) PDUs. No connection setup, no flow or error control. Simplest; higher-layer software handles reliability.
  • Type 2 — Connection-mode: Uses HDLC asynchronous balanced mode. Logical connection established; sequence numbers, flow control (sliding window), and error control provided. More overhead but full reliability.
  • Type 3 — Acknowledged connectionless: Datagrams acknowledged using a new AC (Acknowledged Connectionless) PDU. No prior connection established — a middle ground.

LLC uses Service Access Points (SAPs) — DSAP and SSAP — to multiplex multiple upper-layer protocols over the same MAC connection (analogous to port numbers in TCP/IP).

6 Transmission media for LANs ⌄

Choice of medium is constrained by topology and shaped by capacity, reliability, data type, and environment:

  • Cat-3 UTP (voice grade) — cheapest, already installed in buildings, but limited data rate. Most cost-effective for low-traffic single-building LANs.
  • Shielded TP / baseband coaxial — more expensive, higher data rates. Original Ethernet used baseband coaxial. Now rarely installed; difficult to reconfigure.
  • Broadband coaxial — analog signals at radio frequencies (as in cable TV). Very expensive, hard to maintain. No longer used in new LANs.
  • Cat-5+ UTP — high data rates, widely used in switched star topologies. Dominant in modern installations.
  • Optical fibre — electromagnetic isolation, very high capacity, small size. High component cost and specialised installation skills required. Used for high-speed links (e.g. backbone at 1 Gbps+). Not practical for bus topology (expensive taps).
⚠
Exam note: Bus topology is limited to baseband coaxial. Ring suits high-speed long-distance links but a single repeater failure disables the network. Star topology (using UTP or fibre to a central hub/switch) is the dominant modern layout.

05 — Interconnection

Bridges

A Purpose and key properties of a bridge ⌄

A bridge connects two or more similar LANs that use the same MAC and LLC protocols. Its reasons for use include:

  • Reliability — partitions the network so faults are contained
  • Performance — confines intra-LAN traffic to each LAN; only inter-LAN frames cross the bridge
  • Security — physically separates traffic with different sensitivity levels
  • Geography — allows equipment clusters in different locations to form one logical network

Key design properties of a bridge:

  • Makes no modification to frame content — the exact bit pattern is copied from one LAN to the next; no encapsulation added
  • Contains sufficient buffer space to handle short-term peak arrival rates
  • Contains routing and address intelligence — knows which addresses are on which LAN and which frames to forward
  • Operates at the MAC layer (IEEE 802.1D) and does not contain an LLC layer
  • Transparent to stations — no change required to attached device software
B Spanning Tree Algorithm — solving the loop problem ⌄

When multiple bridges create redundant paths (loops) between LANs, frame forwarding breaks: stations receive duplicate frames, and address-learning databases become corrupted because the same source address appears on multiple ports simultaneously.

The IEEE 802.1D Spanning Tree Algorithm solves this by automatically computing a loop-free subset of active bridges:

  • Each bridge is assigned a unique identifier
  • Bridges exchange configuration messages to elect a root bridge and determine which ports to block
  • The result is a spanning tree — all LANs remain reachable, but no closed loops exist
  • The algorithm is dynamic — when topology changes (a bridge fails or is added), the tree is automatically recalculated

Three mechanisms work together: frame forwarding (lookup destination in forwarding database), address learning (update database with source addresses of arriving frames), and loop resolution (spanning tree algorithm blocks redundant ports).

⚠
Exam note: Address learning uses the source address of arriving frames to populate the forwarding database, and a timer on each entry — expired entries are removed so the database stays current as stations move.
C Fixed routing vs spanning tree routing ⌄
  • Fixed routing — a route for each source–destination LAN pair is manually configured; typically the minimum-hop route is chosen. Simple and low overhead, but requires manual updates whenever topology changes. Suitable for small, stable internets only.
  • Spanning tree routing — bridges automatically discover the topology and derive a loop-free tree. Responds dynamically to failures and additions. The IEEE 802.1D standard approach used in virtually all modern bridged networks.

Conceptual Q1. Why is a LAN's transmission medium described as "shared", and what two problems does this create? ⌄

In a bus, tree, or hub-based star topology, a transmission from any one station propagates throughout the medium and is received by all other stations simultaneously — hence the medium is shared.

This creates two problems:

  • Addressing — because all stations receive every frame, each frame must carry a destination address so stations can determine which frames are intended for them. Stations examine the header and copy only frames addressed to themselves.
  • Access regulation — if two stations transmit simultaneously, signals collide and both frames are corrupted. A MAC protocol is required to regulate when each station may transmit.

Application Q3. A star LAN uses a hub. What happens when two stations transmit simultaneously? How does replacing the hub with a layer 2 switch change this? ⌄

With a hub: The hub is a layer 1 repeater — it retransmits everything it receives on all ports simultaneously. If two stations transmit at the same time, both signals arrive at the hub together and collide. The resulting garbled signal is retransmitted on all ports. Both transmitting stations detect the collision and back off using CSMA/CD. The LAN is logically a bus: all stations share the total capacity (e.g. 10 Mbps), and only one station can successfully transmit at a time.

With a layer 2 switch: The switch maintains a MAC address table and forwards each frame only to the specific destination port. Each port operates on a separate collision domain. Multiple stations can transmit simultaneously to different destinations — total capacity becomes N × 10 Mbps. No collisions occur between ports, and each station effectively has dedicated bandwidth equal to the original LAN speed.

Conceptual Q4. Why is the IEEE 802 data link layer split into MAC and LLC sublayers? ⌄

The split exists for two reasons:

  • MAC is unique to shared media: The logic required to govern access to a shared transmission medium is not found in traditional (point-to-point) data link control. It must be separated so that the shared-access specifics don't pollute the upper-layer interface.
  • LLC can be common across MAC types: By isolating MAC, a single LLC specification can sit above multiple different MAC protocols (Ethernet CSMA/CD, token ring, token bus, Wi-Fi). Upper-layer protocols (IP) interface to LLC without needing to know which underlying MAC technology is in use. This enables interoperability and simplifies design.

Application Q6. Explain what a bridge does with a frame. What information does it need, and how does it acquire it? ⌄

When a bridge receives a frame on port X it:

  1. Searches its forwarding database for the destination MAC address
  2. If the address is listed for port Y (and port Y is not blocked), it copies the exact bit-pattern of the frame to port Y
  3. If the address is not found, it floods the frame to all ports except the incoming port X
  4. If the address is listed for port X (same side as source), the frame is not forwarded — it stays local

Address learning: As frames arrive, the bridge notes the source MAC address and the port it arrived on, and updates the forwarding database accordingly. A timer is associated with each entry; if no frame from that address arrives before the timer expires, the entry is removed. This allows the database to track station movements automatically.

Conceptual Q7. What problem do bridge loops cause, and how does the Spanning Tree Algorithm solve it? ⌄

The loop problem: When two bridges connect the same pair of LANs, a frame transmitted by station A is captured by both bridges and forwarded by each. Station B receives two copies. Each bridge also receives the other's retransmission — which carries A's source address — and incorrectly updates its database to indicate A is on the far LAN. Neither bridge can now correctly forward frames addressed to A. The network is effectively broken.

Spanning Tree Algorithm (IEEE 802.1D) solution: Bridges exchange configuration messages to elect a root bridge and determine the minimum-cost spanning tree — a loop-free subset of bridges that still connects all LANs. Ports on redundant paths are set to blocking state. Blocked ports do not forward frames, eliminating the loop. If the topology changes (bridge failure, addition), the algorithm automatically recomputes the spanning tree.

Application Q9. A company has thousands of PCs, multiple servers, and a WAN connection. Describe the typical large LAN architecture used and the role of each device type. ⌄

A typical large LAN uses a hierarchical design:

  • Desktop/end stations (10–100 Mbps): PCs and workstations connect to layer 2 switches via Cat-5 UTP at 10 or 100 Mbps. Wireless users connect via access points at ~11 Mbps to the same layer 2 switches.
  • Layer 2 switches: Provide dedicated per-port bandwidth to each end station; handle local (intra-subnet) MAC-level forwarding at wire speed; connect upward to layer 3 switches at 100 Mbps to 1 Gbps.
  • Layer 3 switches (backbone): Interconnect subnets at 1 Gbps; perform hardware-speed IP routing between subnets; confine broadcast domains — MAC broadcast frames stay within each subnet circle. Servers connect directly here at 1 Gbps.
  • Software-based router: Connects the internal network to the WAN. Handles inter-organisation routing; does not need hardware speed since WAN bandwidth is the bottleneck, not internal throughput.

This structure gives wire-speed intra-LAN performance, controlled inter-subnet routing, broadcast containment, and scalability — each layer can be upgraded independently.

Conceptual Q10. Why is optical fibre rarely used in bus LAN topologies, yet commonly used in backbone and high-speed links? ⌄

Optical fibre has highly attractive properties — high capacity, electromagnetic isolation, security, and small physical size — but its use in bus topology is impractical for one key reason: the expense of optical taps.

A bus requires every station to physically tap into the shared medium. For coaxial cable, taps are inexpensive passive components. For optical fibre, a tap must split the optical signal, which requires expensive optical couplers that also introduce significant signal loss at every tap point. This makes a multi-station bus over fibre economically and technically unworkable.

In contrast, point-to-point links (as used in star topology connections to a central switch, or in backbone links between buildings) have no tapping problem — each fibre run connects exactly two endpoints. Here the high bandwidth and long-distance capability of optical fibre (up to 500 m and beyond) are fully exploited. This is why modern star-topology LANs commonly use fibre for uplinks and backbone segments, even though it doesn't appear in bus installations.

01 — Core concepts

Topic summaries

1 What is routing? ⌄

Routing is the key design function in packet-switched networks. In general, the routing function seeks to find paths through the network for pairs of communicating nodes such that the network is used efficiently.

The primary function of a packet-switching network is to accept packets from a source station and deliver them to a destination station. To do this, a path through the network must be determined — generally more than one route exists, so a routing decision must be made.

2 Required characteristics of routing ⌄
  • Correctness — routes must actually deliver packets to the right destination
  • Simplicity — the routing algorithm should not impose excessive computational overhead
  • Robustness — the ability to continue delivering packets via some route despite node/link failures and overloads
  • Stability — adaptive techniques must not react so quickly that they cause oscillation, nor so slowly that information is stale
  • Fairness & Optimality — a tension exists between maximising average throughput and treating all flows equitably; some performance criteria may favour nearby stations
  • Efficiency — routing overhead (processing + transmission) must be less than the benefit gained
3 Performance criteria — least cost ⌄

The simplest performance criterion is minimum hop — every link has cost 1 and the route with fewest hops is chosen. More generally this is extended to least cost, where each link is assigned a value reflecting some design objective.

  • Cost inversely proportional to data rate → high-bandwidth links are preferred → maximises throughput
  • Cost proportional to current queuing delay → less-loaded links preferred → minimises end-to-end delay

In the standard 6-node example network: the shortest path (fewest hops) from node 1 to node 6 is 1→3→6 (cost = 5+5 = 10), but the least-cost path is 1→4→5→6 (cost = 1+1+2 = 4).

⚠
Exam note: Minimum hop and least cost can give different routes. Know which criterion is being used and apply it consistently in worked examples.
4 Decision time and decision place ⌄

Decision time refers to when routing decisions are made:

  • Packet (datagram) — a routing decision is made individually for every packet
  • Session (virtual circuit) — one decision is made when the circuit is established; subsequent packets follow the same route

Decision place refers to which node makes the decision:

  • Distributed — each node selects an outgoing link for packets as they arrive. More complex but also more robust. Used in most real networks.
  • Centralized — a network control center makes routing decisions. Efficient but the control center is a single point of failure that can block network operation.
  • Source — the originating host dictates the full route. Allows the user to meet criteria local to that user.
5 Network information source and update timing ⌄

Most routing strategies require knowledge of topology, traffic load, and link cost. The source of that information varies:

  • None — e.g. flooding requires no network information at all
  • Local only — isolated adaptive routing uses only local queue lengths
  • Adjacent nodes — distributed routing; each node exchanges delay/cost info with its neighbours
  • All nodes — centralized routing; a central node collects info from all nodes

Update timing determines how often this information is refreshed:

  • Fixed — routing tables are never updated (unless network topology changes)
  • Adaptive — regular updates allow routing to adapt to changing traffic conditions, failures, and congestion

03 — Least-cost algorithms

Dijkstra's algorithm

Dijkstra finds the shortest (least-cost) paths from a given source node to all other nodes by building up the solution one node at a time in order of increasing cost.

D Algorithm steps (formal) ⌄

Notation: s = source node, T = set of nodes incorporated so far, L(n) = current least-cost estimate from s to n, w(i,j) = link cost from i to j (∞ if not directly connected, 0 if i = j).

Step 1 — Initialisation:

  • T = {s}
  • L(n) = w(s, n) for all n ≠ s (link cost to each neighbour; ∞ if not adjacent)

Step 2 — Get next node:

  • Find the node x not in T with the minimum L(x)
  • Add x to T; also add the edge incident on x that gives the path

Step 3 — Update paths:

  • For all n ∉ T: L(n) = min[ L(n), L(x) + w(x, n) ]
  • If L(x) + w(x, n) is the minimum, path from s to n now goes via x

Repeat Steps 2–3 until all nodes are in T.

⚠
Key point: Dijkstra requires each node to know the complete topology — all link costs across the entire network. This means nodes must exchange link-state information with every other node in the network.

So each node need only know its next hop — the rest of the path follows automatically from the next node's table.

04 — Least-cost algorithms

Bellman-Ford algorithm

Bellman-Ford builds up least-cost paths by progressively relaxing the constraint on the maximum number of links h allowed in a path.

B Algorithm steps (formal) ⌄

Notation: s = source, w(i,j) = link cost, h = current maximum hops allowed, Lh(n) = cost of least-cost path from s to n with at most h links.

Step 1 — Initialisation:

  • L0(n) = ∞ for all n ≠ s
  • Lh(s) = 0 for all h

Step 2 — Update (for each h = 0, 1, 2, …):

  • For each n ≠ s: Lh+1(n) = minj[ Lh(j) + w(j, n) ] where j ranges over all neighbours of n
  • Connect n with the predecessor node j that achieves the minimum
  • Eliminate any earlier predecessor connection to n formed in a prior iteration (if a better path is found)

Continue until no L values change — the algorithm has converged.

⚠
Key distinction from Dijkstra: Bellman-Ford only needs link costs to neighbouring nodes plus the current cost estimates stored at those neighbours. Each node only needs to communicate with its direct neighbours — making it naturally suited to distributed implementations.

06 — Real-world case study

ARPANET routing evolution

The ARPANET provides a concrete case study in how routing algorithms evolved in response to observed problems. Three generations are examinable.

1969
Gen 1

Algorithm: Distributed adaptive using Bellman-Ford; metric = estimated delay (queue length as proxy)

  • Each node periodically (every 128 ms) exchanges its delay vector with all neighbours
  • Nodes update routing tables based on incoming delay vectors

Problems identified:

  • Queue length is a poor delay estimator — ignores link speed entirely
  • Reacts slowly to congestion; packets could chase congestion rather than avoid it
  • Distributed perception of shortest path could change while a packet was en route
1979
Gen 2

Algorithm: Distributed adaptive; metric = measured delay (timestamps)

  • Delay measured directly: departure time − arrival time + transmission time + propagation delay
  • Average delay computed every 10 seconds; significant changes flooded to all nodes
  • Routing recomputed using Dijkstra's algorithm

Performance: Good under light and medium loads

Problem under heavy loads: Measured delay on a link is not a good predictor of delay after all nodes reroute. After a routing update, traffic patterns change — making the routing tables immediately obsolete. Little correlation between reported and experienced delays under high load.

1987
Gen 3

Algorithm: Revised cost function based on utilisation (not raw delay)

  • Average delay over last 10 seconds transformed into a link utilisation estimate using a single-server queuing model
  • Utilisation smoothed by averaging with previous results
  • Link cost set as a function of average utilisation — designed to damp oscillations

Key insight: Under heavy loads, the goal should be to give the average route a good path — not to optimise every route simultaneously (those efforts conflict). The cost function is kept at minimum until a threshold utilisation is reached, then rises to a cap. Acts like a delay-based metric at low loads and a capacity-based metric at high loads.

💡
Pattern to remember: Each generation fixed the previous generation's instability. Gen 1 → queue length unreliable; Gen 2 → delay measurement fine at low load, fails at high load; Gen 3 → switched to utilisation metric with damping to prevent oscillation.

07 — Vocabulary

Key terms & definitions

Routing
The function of finding a path through a packet-switched network from source to destination, seeking efficient network use.
Least-cost path
The path between two nodes whose sum of link costs is minimum. May differ from the minimum-hop (fewest links) path.
Fixed routing
A single permanent route per source-destination pair, determined offline by a least-cost algorithm. Cannot respond to traffic changes.
Flooding
A packet is sent on every outgoing link. Extremely robust; requires no network information; high traffic load proportional to connectivity.
Random routing
One outgoing link is chosen randomly or round-robin. Simple and robust; typically produces neither least-cost nor minimum-hop routes.
Adaptive routing
Routing decisions change in response to changing network conditions (failure, congestion). Requires network state information.
Distributed routing
Each node independently selects an outgoing link for each arriving packet. More robust than centralised; used in most real networks.
Centralised routing
A network control center makes all routing decisions. Efficient but creates a single point of failure.
Source routing
The originating host specifies the complete route in the packet. Allows user-defined paths; used in some internet protocols.
Dijkstra's algorithm
A greedy least-cost algorithm that adds nodes one at a time in order of increasing cost. Requires full network topology.
Bellman-Ford algorithm
An iterative least-cost algorithm that relaxes the hop-count constraint. Suited to distributed operation — only neighbour info needed.
Lh(n)
In Bellman-Ford: the cost of the least-cost path from source s to node n, constrained to at most h links.
Hop count
Number of links traversed in a path. Minimum-hop routing assigns cost 1 to every link; simpler but ignores link capacity and load.
Routing oscillation
Instability caused by adaptive routing reacting too quickly — traffic shifts cause link costs to change, shifting traffic back, causing cycles.
Link utilisation metric
A routing cost based on the fraction of capacity in use on a link. Used by ARPANET Gen 3 to damp oscillation and reduce overhead.
Network diameter
The length (in hops) of the longest minimum path between any two nodes. Used to initialise the hop-count field in flooding.

Application Q5. In the standard 6-node network, run Dijkstra's algorithm from node 1. What is the least-cost path to node 6, and what is its cost? ⌄

Conceptual Q6. State the Bellman-Ford update equation and explain in words what it computes. ⌄

The update equation is: Lh+1(n) = minj[ Lh(j) + w(j, n) ]

where j ranges over all neighbours of node n.

In words: the least-cost path from source s to node n using at most h+1 links is found by considering all of n's neighbours j, and selecting the neighbour j that minimises the sum of: the current best cost from s to j (using at most h links), plus the direct link cost from j to n. The path then goes s → … → j → n.

The algorithm is initialised with L0(n) = ∞ for all n ≠ s, and converges when no values change between iterations.

Compare Q7. Compare Dijkstra and Bellman-Ford in terms of information requirements and suitability for distributed vs centralised routing. ⌄

Dijkstra requires each node to have the complete network topology — all link costs everywhere. Nodes must exchange link-state information with every other node. This is well-suited to centralised or link-state routing (e.g. OSPF), where a full topology map is maintained.

Bellman-Ford only needs each node to know its link costs to direct neighbours, plus cost estimates from those neighbours. Nodes only need to communicate with adjacent nodes — making it naturally suited to distributed, distance-vector routing (e.g. RIP). Each node maintains a table of estimated costs to every destination and shares it with neighbours.

Both algorithms produce identical results and converge under static conditions.

Conceptual Q9. Explain why only the "next node" needs to be stored in a routing table rather than the complete path. ⌄

Suppose the least-cost path from X to Y goes X → A → … → Y. Call the portion from A to Y "R1", and define R2 as the least-cost path from A to Y independently.

  • If cost(R1) > cost(R2), then the original path X → A → R1 → Y is not optimal — it can be improved by using R2. Contradiction.
  • If cost(R1) < cost(R2), then R2 is not the least-cost path from A to Y. Contradiction.
  • Therefore cost(R1) = cost(R2), meaning R1 is the least-cost path from A to Y.

This means: once X forwards the packet to A, node A's own routing table will correctly continue the path to Y. Every node only needs to know the next hop — the rest of the path is handled recursively by subsequent nodes' tables.
